# Rails 7.0.8.7 → 8.1.0: Margin Notes upgrade plan

## Recommendation

**Do not deploy a version-only bump. Upgrade through 7.1 → 7.2 → 8.0 → exactly 8.1.0, preserving `config.load_defaults 7.0` initially.** Several removals apply regardless of that setting. Deploy compatible preparations first; adopt new defaults separately after stored-data and mixed-worker compatibility checks.

The app currently runs Ruby **3.3.6**, which satisfies Rails 8.1.0's Ruby ≥ 3.2 requirement. PostgreSQL, Sprockets/importmap, the existing authentication, and Sidekiq can remain. A Rails upgrade does **not** require Propshaft, Solid Queue/Cache/Cable, Kamal, the new authentication generator, `params.expect`, or a browser-version guard.

**No working application code, Gemfile, lockfile, database, queue, cache, or storage was changed.** Experiments used disposable checkouts, an independent PostgreSQL cluster and Redis process, copy-local caches/storage, and test email delivery. Only this ignored report/evidence and a repository-local artifact exclusion were added. Nothing was committed or published.

### Evidence and limits

- **Executed, current app:** Rails 7.0.8.7, original application code and locked dependencies, isolated resources: **46 tests, 325 assertions, 0 failures/errors/skips**.
- **Executed, version-only target:** dependencies resolved with Rails **8.1.0**, Sidekiq **6.5.12**, Redis gem **4.8.1**, Rack **2.2.24**, Puma **5.6.9**, pg **1.6.0**. Boot **failed** at `config/initializers/action_text.rb` because `allowed_tags` is now nil. This is not an 8.1 test-suite pass.
- **Executed, dependency variant:** the unconstrained target resolved **json 3.1.0**, breaking Rails 8.1.0 JSON decoding. A second variant added only `json < 3`, resolving **json 2.21.2**, and removed that particular failure. Other application incompatibilities remain.
- **Executed, framework probes:** versioned API calls, isolated PostgreSQL operations, JSON-round-tripped Active Job arguments in both directions, and controller/view HTTP probes. These support the specific observations below, not an end-to-end upgraded-app certification.
- **Source review:** exact Rails tags **7.0.8.7, 7.1.0, 7.2.0, 8.0.0, 8.1.0**, upgrade/release guidance, the app's models/controllers/views/configuration/schema/tests. The online `/v8.1/` guide currently includes later patch changes; exact-tag source governs conclusions about **8.1.0**.
- **Not executed:** intermediate Rails app suites, corrected 8.1 app suite, full-defaults app suite, browser tests, asset precompile, real Sidekiq worker consumption, deployment/rollback, or production-data inspection. No actual system tests exist under `test/system`; the Selenium base class alone is not coverage.

See [commands, configuration and experiment attribution](evidence/COMMANDS.md), [full dependency snapshots](evidence/dependencies/), and [logs](evidence/logs/). “Compatible on 7.0” below means source-compatible unless an executed probe is explicitly identified; it does not mean an application patch was implemented or tested.

## Required compatibility work

### 1. Constrain the newly resolved JSON dependency; do not invent a Rack conflict

**Affected:** [Gemfile](file:///home/user/workspace/repo/Gemfile#L4-L36), [Note settings/tags](file:///home/user/workspace/repo/app/models/note.rb#L12-L14), Active Storage metadata and other framework JSON readers.

**Condition/change:** Rails 8.1.0 adds an unconstrained JSON gem dependency. Today's resolution selected JSON 3.1.0. Rails 8.1.0 `ActiveSupport::JSON.decode` calls `JSON.parse(json, options)` positionally; JSON 3 requires keyword options. The experiment hit `ArgumentError: wrong number of arguments (given 2, expected 1)` while reading a JSONB default. This is a real resolved-dependency failure, not evidence that Rails 8.1 itself needs Rack 3.

**Recommendation:** for this exact target, add `gem "json", "< 3"`, retain the reviewed lockfile, and test the resulting version. The tested resolution is 2.21.2. Keep unrelated dependency pins in the first Rails change. Current Ruby's default JSON 2.7.2 already falls within the bound; installing a newer 2.x on the current app is still a separately proposed baseline check. Do not infer all JSON 2.x releases are certified by one run.

**Validation:** read and update existing `notes.settings`, JSON tags and blob metadata, then rerun the whole suite and asset build. Reproduce the failing `ActiveSupport::JSON.decode` call against the locked variant. The probe's success after the bound is not a full application pass.

**Sidekiq:** Rails 8.1's built-in adapter is **deprecated**, not removed; removal is announced for 8.2. Upstream recommends Sidekiq ≥ 7.3.3 for its own adapter. That is a separate modernization decision, not a proven requirement for 8.1.0. If chosen, audit native `ExportJob`'s symbol-keyed `{ format: "markdown" }`, Redis command return values in `User#request_digest`, error classes, and retry/scheduled payloads. Do not combine it silently with this upgrade.

### 2. Repair Action Text initialization without discarding its default allowlist

**Affected:** [initializer](file:///home/user/workspace/repo/config/initializers/action_text.rb#L1-L3), [rich text attachment rendering](file:///home/user/workspace/repo/app/views/active_storage/blobs/_blob.html.erb#L1-L19), stored `action_text_rich_texts.body`.

**Condition/change:** since 7.1, `ContentHelper.allowed_tags` is an optional override; the effective default is derived by the helper. The current `allowed_tags += …` fails on nil, including with 7.0 defaults. This was the **executed target boot failure**.

**Recommendation:** initialize an explicit full allowlist from the effective sanitizer's safe tags plus `ActionText::Attachment.tag_name`, `figure`, `figcaption`, `details`, and `summary`. Preserve default safe attributes/attachment attributes. Do not use `allowed_tags ||= []` and append just two tags: that would strip ordinary formatting and attachment markup. Arrange initialization after the sanitizer vendor is selected if adopting HTML5 later.

**7.0 preparation:** an explicit complete allowlist works on the current API; verify it there first. No stored HTML rewrite is required.

**Validation:** render pre-existing HTML containing links, a signed attachment, `details/summary`, malformed nesting, and unsafe `script`, event handlers and `javascript:` URLs. Check both permitted content and rejected content. Existing tests cover some simple cases but not malformed historical HTML across vendors or old signed attachments.

### 3. Update Note APIs, preserving the physical data formats

**Affected:** [Note declarations](file:///home/user/workspace/repo/app/models/note.rb#L10-L14), [Notebook preferences](file:///home/user/workspace/repo/app/models/notebook.rb#L7-L19), [notes schema](file:///home/user/workspace/repo/db/schema.rb#L96-L118).

- **Enum:** keyword declarations are removed in 8.0. Use `enum :status, { draft: 0, ready: 1 }, prefix: true`, retaining the integer mapping and `status_ready`/`status_draft` interface. This syntax was **probed successfully on 7.0 and 8.1**. The other two app enums already use it.
- **JSON tags:** positional coders are removed in 7.2. On **7.1 or later**, use `serialize :tags, coder: JSON`. **Do not deploy that change on 7.0.8.7.** An executed 7.0 probe accepted the keyword but wrote `---\n- a\n- b\n` (YAML), whereas the intended JSON is `["a","b"]`. A syntactically successful “preparation” can corrupt the cross-version contract.
- **Highlight alias:** `color` is a `store_accessor`, not a database column. Rails 7.2 removes this use of `alias_attribute`; the target probe raised. Replace with real reader and writer aliases/delegation to `color`/`color=`. Both directions matter because forms read and assign `highlight_color`. This can be prepared on 7.0; keep `settings` JSONB as-is.
- **Preferences:** `serialize :preferences` continues to use YAML with retained 7.0 defaults, but `load_defaults 7.1+` sets the default column serializer to nil. At the 7.1 stage make this explicit as `serialize :preferences, coder: YAML`, retaining safe YAML handling. Do **not** switch historical preferences to JSON or add restrictive types without a data inventory. Keyword serialization is not a general 7.0-compatible change, even where a YAML default happens to make it look harmless.

**Validation:** create fixtures through the 7.0 writer, then read/update/re-read through the new writer and the rollback reader. Include nonempty tags, empty arrays, Unicode, null preferences, and a nonempty export heading. Inspect raw SQL values as well as Ruby values; tests that create and read exclusively with the same wrong serializer can pass. Inventory real preferences for YAML object classes before changing permitted types. No enum renumbering or schema/data migration is needed for these API changes.

### 4. Preserve atomic imports, annotations and DOI receipts

**Affected:** [Import#apply / #receipt](file:///home/user/workspace/repo/app/models/import.rb#L50-L71), [preview annotations](file:///home/user/workspace/repo/app/views/imports/preview.html.erb#L22-L44), `citations.doi` primary key.

1. **Partial commit:** `return false` from inside the transaction currently rolls back. Rails 7.1 defaults can commit it; 7.2 removes the old rollback behavior. The isolated database probe changed from **zero** inserted rows on 7.0 to **one** on 8.1 for the same early return. Raise `ActiveRecord::Rollback` when a row save fails; return true only after all rows save, and normalize the transaction result to false outside it. Keep row validation errors for the preview. This works on 7.0; an explicit-rollback probe rolled back on both versions.
2. **Blank DOI receipts:** Rails 7.2 removes `read_attribute(:id)`'s fallback to a custom primary key. `citation[:id]` became **nil** in the target probe. Use `citation&.doi` (or `citation.id`), without altering primary keys or foreign keys. Compatible with 7.0.
3. **Missing annotations:** Rails 8.0 makes `HashWithIndifferentAccess#stringify_keys` stringify integer keys too. The preview converts keys then indexes with integer `row.line`, so annotations disappear. Remove the unnecessary conversion and keep integer lookups, or consistently use string keys at both ends. Removing it is compatible with 7.0 and was probed on both versions.

**Validation:** import a valid first row and invalid second row, and assert **Import, Note, Citation and ActionText rows all remain unchanged**, including outside a test's enclosing transaction. Use distinct annotations on lines 2 and 4 with a multiline CSV body. Download a receipt for repeated `10.1000/Essays.1` and a blank DOI. Existing tests already express much of this contract; preserve their expectations rather than weakening them.

### 5. Keep both note-list routes and the unbound search form

**Affected:** [routes](file:///home/user/workspace/repo/config/routes.rb#L17-L19), [search form](file:///home/user/workspace/repo/app/views/notes/index.html.erb#L12).

**Condition/change:** multi-path route calls are removed in 8.1; `form_with(model: nil, …)` is removed in 8.0. Both exact patterns failed in the target protocol probe.

**Recommendation:** declare `/notes` and `/journal` separately, preserving `notes_path` and `journal_path` (explicit `as:` is clear). Omit the `model:` option for the GET search form. Both replacements were **probed on 7.0 and 8.1**.

**Validation:** request both routes while signed in/out, confirm identical ownership/filtering/pagination, and submit the unbound search form in a browser. Do not change canonical URLs or bookmark behavior as part of the API correction.

### 6. Replace application secrets access before 7.2

**Affected:** [Citation::Provider](file:///home/user/workspace/repo/app/models/citation/provider.rb#L1-L15), [secrets.yml](file:///home/user/workspace/repo/config/secrets.yml), [provider tests](file:///home/user/workspace/repo/test/controllers/citation_enrichments_controller_test.rb).

**Condition/change:** `Rails.application.secrets` is deprecated in 7.1 and removed in 7.2. The app really uses it for provider URL/basic-auth settings; tests also mutate/read it.

**Recommendation:** move these environment-backed settings into a normal `config_for(:citation_provider)` configuration assigned to `config.x.citation_provider`, or directly configured environment-backed `config.x` values. Preserve the current development/test stand-in defaults, production's missing-provider behavior, and literal string credentials. Replace all test accesses and the fresh-process credential test. Remove obsolete citation-only `secrets.yml` after its consumers are migrated; do not rotate secrets or move actual credentials without checking the deployment's source.

**7.0 preparation:** `config_for` and `config.x` are available now; this migration can precede Rails. **Validation:** retain the real loopback HTTP test using `00123` and `sample: value # keep`, with a fresh process for environment reads, and exercise unconfigured production behavior in an isolated environment. Real production credential provisioning was not inspected.

### 7. Preserve citation retries and reminder instants

**Affected:** [CitationEnrichmentJob](file:///home/user/workspace/repo/app/jobs/citation_enrichment_job.rb#L7-L9), [Note#schedule_reminder](file:///home/user/workspace/repo/app/models/note.rb#L55-L70), [postponement preview](file:///home/user/workspace/repo/app/models/note.rb#L40-L45).

- **Retry algorithm:** change `:exponentially_longer` to `:polynomially_longer` at **7.1**, before the former is removed in 7.2. The algorithm remains the fourth-power backoff plus jitter, not an exponential redesign. **Not compatible with 7.0**: the new symbol failed in the baseline probe; the old one failed in the target probe. If a shared pre-upgrade implementation is unavoidable, a proc must preserve the original jitter too; simply using `executions**4 + 2` drops behavior. Prefer the staged symbol change.
- **Scheduling:** numeric `wait_until` becomes invalid after the 7.1 deprecation/7.2 removal. Pass `Time.at(reminder_epoch).utc`; keep the database value as epoch seconds. Numeric input raised `undefined method utc` in 8.1; the Time replacement worked on both versions.
- **DST representation:** in 8.1 `TimeWithZone#to_time` always retains the named zone, regardless of retained defaults. The same postponed instant changed from `2026-11-01T09:00:00-04:00` to `2026-11-01T08:00:00-05:00`. **The epoch is unchanged.** To preserve this app's documented fixed-offset preview, explicitly use `time.to_time.getlocal(time.utc_offset) + 86_400`. That expression was probed on both. Alternatively adopt a zone-aware preview intentionally and update its documented/tested presentation contract. Do not replace 86,400 seconds with `1.day`: that changes the instant across DST.

**Validation:** unavailable citation responses must still give three job attempts, up to six HTTP calls, correct delay ranges, then a persisted failure. Schedule at an asymmetric epoch including nonzero seconds; test spring-forward and fall-back, superseded scheduled IDs, deleted notes and Redis refusal. Inventory existing scheduled/retry entries; old reminder envelopes can omit `scheduled_at`, which the new deserializer accepts. Keep job classes, GlobalIDs and stored job IDs stable; do not cancel or re-create every scheduled reminder merely to upgrade.

### 8. Make digest UTC-day and queue-wire contracts explicit

**Affected:** [User#request_digest](file:///home/user/workspace/repo/app/models/user.rb#L34-L58), [DigestJob](file:///home/user/workspace/repo/app/jobs/digest_job.rb), [DigestMailer](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L6-L12), digest reservation keys in Redis.

**Condition/change:** 7.2 serializes a `TimeWithZone`'s zone name. The app currently relies on 7.0 losing that zone and reconstructing the time in UTC. With 8.1, a request at 2026-10-05 03:30 UTC remains October 4 in New York in the worker: the mailer's day/range diverges from its **October 5 UTC reservation key**. This is independent of `load_defaults`.

Separately, the 7.1 optional/7.2 mandatory BigDecimal serializer adds a new `_aj_serialized` class. **Executed cross-version result:** new workers read old decimal strings; 7.0 workers cannot read new BigDecimal envelopes. The error is an unknown serializer, not a mailer arithmetic failure. `BigDecimal(existing_big_decimal)` itself worked in the tested versions; no speculative mailer conversion rewrite is required.

**Recommendation, compatible with 7.0:** normalize `requested_at` to UTC in the mailer before computing both date and `all_day`, so already queued zoned jobs are handled. Make new producers send `requested_at.utc` and `reading_completion.to_s("F")`. Keep the existing UTC reservation keys and two-day TTL. The prepared primitive wire arguments were probed on both versions.

**Validation:** produce on each version and consume on each version **after a real JSON/Redis boundary**. Use a nonzero, nonterminating ratio such as 2/3 (0.6667), New York near UTC midnight, and ready notes on both neighboring UTC/local days. Assert day, included/excluded note titles, percentage and one-request-per-UTC-day behavior. Current Active Job test-adapter tests do not reproduce Sidekiq's JSON conversion. This particular change needs mixed-version tests even if the entire application suite passes.

**Rollout:** deploy the UTC consumer normalization and primitive producer contract before any incompatible producers. Drain/inspect old-format immediate, scheduled and retry work; old producers still running can continue to produce old payloads. If new BigDecimal envelopes have already been emitted, a rollback to unprepared 7.0 requires draining/converting those queues or a tested compatible reader first. Do not flush Redis: it also holds digest deduplication state and unrelated queued work.

### 9. Preserve Markdown generation and guard expired fragment caching

**Affected:** [Export#generate](file:///home/user/workspace/repo/app/models/export.rb#L32-L43), [export availability fragment](file:///home/user/workspace/repo/app/views/exports/_export.html.erb#L25-L39), [download authorization/conditional GET](file:///home/user/workspace/repo/app/controllers/export_downloads_controller.rb#L5-L20).

**Condition/change:** Rails 7.1 removes the special string-friendly `Enumerable#sum`; `fragments.sum` raises on 8.1. Use `fragments.join`, which was probed on both versions and preserves output bytes.

The fragment passes `expires_at - Time.current` even after expiry. On 7.0 a negative TTL produces an already-expired entry; in newer Rails with legacy defaults it is ignored (the probe could read the value without an expiry). With 7.1+ defaults it raises. **This is not fixed by retaining 7.0 defaults.** The strict error is default-dependent; the TTL behavior change is not.

**Recommendation, compatible with 7.0:** calculate the TTL once and only cache the availability fragment when it is positive, otherwise render the expired state uncached. `cache_if ttl.positive?` with a positive captured `expires_in` avoids feeding a negative TTL at the boundary. Keep the authoritative ownership/status/deadline checks before `stale?`; a cache must never authorize a download.

**Validation:** verify byte-exact Markdown for zero, one and multiple notes, cancellation and retry. Exercise **cold and warm caches**, immediately before, exactly at, and after the deadline, with caching actually enabled and both old/new expiration settings. Check expired and foreign-owner requests with matching ETag/Last-Modified remain denied. Current tests use MemoryStore for their cache case, not production's default FileStore.

## Delivery sequence and rollback gates

1. **Baseline and inventories.** Record dependency lockfiles and effective defaults; use the passing isolated baseline above. Before touching shared systems, inventory production serialized tags/preferences, rich-text attachments and signing-key sources, Sidekiq queues/retry/scheduled/dead sets, active exports, and cache topology. No production inventory was performed in this audit. Back up database **and attachment files together**; Disk storage must remain reachable by web and worker releases.
2. **Deploy current-version-safe preparations.** Explicit safe allowlist, positional enum, real highlight aliases, primitive/UTC digest contract, Time scheduling, deterministic DST preview policy, string joining, explicit import rollback, DOI receipt access, integer annotation keys, separate routes, omission of `model:nil`, provider configuration migration, and TTL guard. Optionally prepare slug/date code for later defaults. Extend existing tests at their public boundaries. Do not yet change serializer keyword syntax, retry symbol, exception symbols, or framework-specific enqueue attributes.
3. **7.1 compatibility checkpoint.** Choose and lock a reviewed 7.1 patch, run the update task only in a reviewable branch/copy, merge changes rather than accepting generated replacements. Keep 7.0 defaults. Change serializer syntax, retry symbol and exception setting now; preserve local secret continuity. Verify that already stored JSON/YAML and queued jobs read identically. The intermediate patch selection and resolution remain proposed, not executed here.
4. **7.2, then 8.0, then exact 8.1.0 checkpoints.** Repeat resolution, eager boot, tests, real-queue probes and artifact review at each step. Retain Sidekiq/Puma/Redis/Sprockets initially. Lock the JSON 2.x constraint for the tested target. Review Trix asset adoption separately. Do not blindly run framework installers over customized views or existing storage tables.
5. **Canary with compatible producers and consumers.** Before mixing nodes, run old-producer/new-worker and new-producer/rollback-worker tests using actual job envelopes. Bring up capable workers before enabling any new payload format; stop old producers before declaring old work drained. Include scheduled reminders and retries, not only queue length zero. For native exports, preserve class/ID/options format, DB status and attached files; no queued-work schema migration is required by the proposed API changes.
6. **Rollback while writers remain compatible.** Roll back application/gems together, not only the Gemfile. Keep the primitive digest wire contract, tag JSON, preferences YAML, original secrets and legacy signing formats. If incompatible signed tokens/new serialized jobs have been written, establish a tested reader-compatible rollback floor (for example a prepared intermediate release), rather than promising an unconditional return to unprepared 7.0. Do not delete unsent reminders or digest reservations. Cache entries can be discarded; user data/queue entries cannot.
7. **Adopt defaults separately.** Enable individual flags only after their discriminating checks. Hold off on `load_defaults 8.1` until all applicable differences above are addressed. When eventually dumping the schema, expect 8.1's alphabetical column ordering; it is not a table/data migration. Rails 8.0's fresh-database migration task can load the schema instead of replaying history, so validate both a disposable schema load and historical migration replay if replay remains an operational requirement. Keep existing migration versions; do not rewrite history to make it look native to Rails 8.1.

No destructive schema conversion is indicated by the inspected usage. Recheck Active Storage/Action Text install migrations at each checkpoint rather than assuming every upgrade needs new tables.

What supplies production `secret_key_base` and mailer settings? These are **unverified**, and determine deployment details, not whether the source incompatibilities apply.
- Are there historical YAML classes, malformed JSON, stale attachment SGIDs, or delayed jobs older than a normal deploy window? Only synthetic data was inspected; do not declare a data migration safe without a read-only production inventory.
- Verify the full prepared application with **both retained defaults and individually enabled new defaults**, plus production-mode boot/assets and real worker scheduling/retry/error paths. Current passing tests establish the baseline, not completeness.

The 8.1 move of rich-text embed assignment from before-save to before-validation makes “rejected note leaves prior persisted body/attachments unchanged” especially worth checking, rather than asserting callback order.
