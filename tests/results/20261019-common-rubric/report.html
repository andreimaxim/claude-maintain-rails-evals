Model accuracy, cost and time

Each model used the original prompt to assess an upgrade from Rails 7.0.8.7 to 8.1.0. The graphs show 44 runs across nine combinations of model and thinking effort, scored against the same 23 expected changes.

Accuracy = changes located ÷ 23. A change counts when the report describes it and names the affected application file, even without explaining the impact or suggesting a fix.

How the scores were calculated. Opus 5.5 at high effort graded every report using the same rules. Each score counts the expected changes marked as located, including findings in linked reports. The score does not measure factual correctness or agreement on risk levels.

How to read the medians. A median is the middle value after sorting the results, or the average of the middle two values for an even number of results. Accuracy, cost and time are calculated separately, so a large point may not match any individual run. Each small point shows the measured result without moving it to avoid overlap.

Limits. Opus high has four runs, and every other combination has five. Runs without complete cost estimates are left out of both graphs and the table. The sample is small, and the results compare the model, effort and software used together. The Claude Code and Amp runs were collected on different dates.

The report uses only the original prompt. No new evaluations are running.
