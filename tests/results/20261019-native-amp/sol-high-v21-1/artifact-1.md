### Evidence and rating conventions

**Changelog** means an upstream release entry; **upstream code** means released source or a linked PR/commit; **application code** means the cited repository call site. **Inference** means the predicted application consequence, not an executed result. No upgraded application or tests were run, and no upgrade was installed. Released Rails trees for 7.0.8.7, 7.1.0, 7.2.0, 8.0.0, and 8.1.0 were compared, changelogs screened, relevant implementations read, and the resolved non-Rails gem sources/history reviewed. This is a targeted assessment, not an exhaustive audit of every intervening patch.

High follows the requested rubric: silent changes to used behavior, data, caching, connections, or mixed-version jobs. It does not mean every finding is a likely catastrophic failure. Conditional or unproven impacts are identified explicitly.

## 2. High-risk changes

### H1. A failed CSV import can commit a partial batch

- **Before → after — changelog + upstream code:** 7.0 rolls back a written transaction exited by nonlocal `return`. From 7.2, that exit commits unless an exception triggers rollback. Keeping 7.0 defaults no longer preserves the old behavior. [Removal commit and tests](https://github.com/rails/rails/commit/eccc6061f4f3abdfdeb9a363987a898418d9498f).
- **Application code:** [Import#apply](file:///home/user/workspace/repo/app/models/import.rb#L50-L60) saves the import and preceding notes, then executes `return false unless row.note.save` inside the transaction.
- **Consequence — inference:** If a later row fails validation, the method still returns false but earlier writes can remain. This contradicts the all-or-nothing import contract and makes retries capable of duplicating already-imported notes. Review explicit rollback/result handling; merely returning false is not rollback. A useful future check is a valid first row followed by an invalid second row, asserting zero persisted batch records.

### H2. Import receipt DOIs silently become blank

- **Before → after — changelog + upstream code:** `read_attribute(:id)`/`record[:id]` previously redirected to a custom primary key; 7.2 removes that translation. `id` remains the primary-key accessor, but `[:id]` reads the literal column. [Removal entry](https://github.com/rails/rails/blob/v7.2.0/activerecord/CHANGELOG.md#L421-L427), [released reader](https://github.com/rails/rails/blob/v8.1.0/activerecord/lib/active_record/attribute_methods/read.rb#L29-L35).
- **Application code:** [Receipt generation](file:///home/user/workspace/repo/app/models/import.rb#L63-L69) reads `citation[:id]`; [citations have a `doi` primary key and no `id` column](file:///home/user/workspace/repo/db/schema.rb#L55-L62).
- **Consequence — inference:** Existing citations can yield nil for the receipt DOI without an exception. Use the actual DOI/primary-key accessor and review downloaded receipts; this is not a database migration or loss of the stored DOI.

### H3. Import preview annotations disappear

- **Before → after — changelog + upstream code:** `HashWithIndifferentAccess#stringify_keys` used to duplicate the hash while leaving integer keys alone; Rails 8 stringifies those too. [PR #53125](https://github.com/rails/rails/pull/53125) explicitly treats this longstanding behavior correction as non-backportable.
- **Application code:** [Annotations are keyed by integer source line](file:///home/user/workspace/repo/app/models/import.rb#L37-L41); [the preview calls `stringify_keys`](file:///home/user/workspace/repo/app/views/imports/preview.html.erb#L22-L25), then [indexes with the integer](file:///home/user/workspace/repo/app/views/imports/preview.html.erb#L42-L44).
- **Consequence — inference:** Line 2 becomes key `"2"`; lookup with 2 misses, so the annotation is omitted from preview. Persistence still uses the original row annotation. Keep one consistent key representation.

### H4. New BigDecimal job payloads are unreadable by old workers

- **Before → after — changelog + upstream code:** 7.0 treats BigDecimal as a primitive argument; JSON-backed Sidekiq turns it into a decimal string. 7.1 introduced a named BigDecimal serializer and rollout flag; 7.2 removed the primitive serializer, and 8.0 removed the flag. New payloads identify `ActiveJob::Serializers::BigDecimalSerializer`, absent from 7.0. [7.1 migration entry](https://github.com/rails/rails/blob/v7.1.0/activejob/CHANGELOG.md#L142-L157), [7.2 removal](https://github.com/rails/rails/blob/v7.2.0/activejob/CHANGELOG.md#L59-L65), [target serializer](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/serializers/big_decimal_serializer.rb).
- **Application code:** [User#request_digest](file:///home/user/workspace/repo/app/models/user.rb#L34-L56) enqueues `reading_completion`; [DigestJob](file:///home/user/workspace/repo/app/jobs/digest_job.rb#L6-L7) forwards it to [DigestMailer](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L7-L10).
- **Consequence — inference:** An old worker consuming a new-format digest raises a deserialization error. New workers can still receive old string arguments, and the mailer's `BigDecimal(...)` handles either a string or BigDecimal. Plan producer/consumer sequencing and rollback, including retry/scheduled queues; do not assume changing `load_defaults` avoids this. A staged compatibility deployment or controlled queue drain needs a deliberate rollout plan.

### H5. Digest content switches from the UTC day to the reader's local day

- **Before → after — changelog + upstream code:** 7.0.8.7's TimeWithZone serializer restores an argument in the worker's zone. The target carries the IANA zone and restores it; old payloads without that field retain the worker-zone fallback. [PR #50240](https://github.com/rails/rails/pull/50240), [target source](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/serializers/time_with_zone_serializer.rb). Although the PR discussion mentions backports, the actual 7.0.8.7 released source was checked and still has the old implementation.
- **Application code:** [Request time is reader-zoned, but reservation keys use UTC dates](file:///home/user/workspace/repo/app/models/user.rb#L34-L41). [DigestMailer chooses its date and query interval from the deserialized time](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L6-L12).
- **Consequence — inference:** At 03:30 UTC on 5 October 2026, an Eastern reader's argument is 23:30 on 4 October. Old processing selects 5 October's UTC notes; new processing selects 4 October's local-day notes, while both reserve the 5 October UTC key. Subjects and included notes change silently, and old/new payloads or workers can produce different day semantics. Decide whether UTC remains the contract and normalize explicitly if so.

### H6. Reminder postponement previews change across DST

- **Before → after — changelog + upstream code:** Under existing defaults, `TimeWithZone#to_time` preserves a fixed UTC offset. Rails 8.1 always preserves the receiver's full time zone, regardless of the old compatibility setting. [8.1 removal entry](https://github.com/rails/rails/blob/v8.1.0/activesupport/CHANGELOG.md#L15-L22), [target implementation](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/time_with_zone.rb#L494-L498).
- **Application code:** [Note#next_day_reminder_at](file:///home/user/workspace/repo/app/models/note.rb#L35-L44) converts then adds 86,400 seconds; [the preview displays its wall-clock time and offset](file:///home/user/workspace/repo/app/views/notes/_reminder.html.erb#L16-L20). [Postponement schedules the resulting epoch](file:///home/user/workspace/repo/app/models/note.rb#L71-L72).
- **Consequence — inference:** Starting 31 October 2026 at 09:00 Eastern, old preview is 1 November 09:00 −04:00; new preview is 08:00 −05:00. **These are the same instant:** the 24-elapsed-hour schedule does not itself shift. The preview and its offset become locally accurate but differ from the old UI contract/comments. Verify both DST boundaries rather than changing the operation to a calendar day unintentionally.

### H7. Expired export fragments lose their negative TTL

- **Before → after — changelog + upstream code:** A negative `expires_in` formerly produced an already-expired cache entry. Target code deletes that option and reports/logs an error; with retained 7.0 defaults it does **not** raise. With no store-wide TTL here, the replacement entry has no expiry. [7.1 entry](https://github.com/rails/rails/blob/v7.1.0/activesupport/CHANGELOG.md#L861-L867), [target option handling](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/cache.rb#L909-L944).
- **Application code:** [The export availability fragment](file:///home/user/workspace/repo/app/views/exports/_export.html.erb#L25-L36) computes the TTL even for expired completed exports.
- **Consequence — inference:** Visiting an expired export can log an error and cache its **Expired** indicator indefinitely until invalidation/eviction, instead of honoring the supplied deadline. This changes cache retention, not ordinarily the correctness of that expired label. It is **not an authorization bypass**: [downloads check authoritative expiry before `stale?`](file:///home/user/workspace/repo/app/controllers/export_downloads_controller.rb#L4-L15). Avoid negative TTL calls; adopting 7.1+ defaults would instead make this path raise.

### H8. Development/test secret selection can invalidate sessions and stored attachment signatures

- **Before → after — changelog + upstream code:** The local generated-key filename changes from `tmp/development_secret.txt` to `tmp/local_secret.txt`; 8.1 additionally prefers `SECRET_KEY_BASE` or encrypted credentials even in local environments. [Upgrade guide](https://github.com/rails/rails/blob/v8.1.0/guides/source/upgrading_ruby_on_rails.md#L169-L177), [8.1 entry](https://github.com/rails/rails/blob/v8.1.0/railties/CHANGELOG.md#L156-L163).
- **Application code:** [Sign-in stores a session](file:///home/user/workspace/repo/app/controllers/application_controller.rb#L7-L17), [notes persist rich text](file:///home/user/workspace/repo/app/models/note.rb#L8), and [blob links use Rails signed paths](file:///home/user/workspace/repo/app/views/active_storage/blobs/_blob.html.erb#L2-L11).
- **Consequence — inference, conditional:** If the selected secret changes, local sessions and signatures derived from it stop validating, including embedded Action Text attachment references. Copying/renaming the old file only preserves fallback behavior; it does not override an ENV/credentials key selected first by 8.1. Actual key sources were intentionally not read, so occurrence is unconfirmed. Preserve the selected key deliberately if local persisted attachments matter. No production key change is established by this finding.

### H9. Uploaded attachment filenames are sanitized differently

- **Before → after — changelog + upstream code:** Rails 8 adds `<`, `>`, `?`, `*`, and `"` to the characters replaced by `-` in `ActiveStorage::Filename#sanitized`. [8.0 entry](https://github.com/rails/rails/blob/v8.0.0/activestorage/CHANGELOG.md#L22-L25), [released implementation](https://github.com/rails/rails/blob/v8.1.0/activestorage/app/models/active_storage/filename.rb#L57-L65).
- **Application code:** [Attachment captions, image alt text, and download URLs](file:///home/user/workspace/repo/app/views/active_storage/blobs/_blob.html.erb#L2-L11) consume `blob.filename`.
- **Consequence — inference:** A filename such as `chapter?draft.pdf` is exposed as `chapter-draft.pdf`. This changes visible/downloaded names and generated paths without rewriting the raw stored filename. Whether existing uploads contain those characters is unknown; generated slug-based Markdown filenames do not exhibit this case.

### H10. Test requests stop honoring Boolean `show_exceptions = false`

- **Before → after — changelog + upstream code:** Boolean values were replaced by `:all`, `:rescuable`, and `:none`; 7.2 removes Boolean compatibility. In the target's `ExceptionWrapper#show?`, false falls through to showing exceptions rather than disabling exception rendering. [Removal entry](https://github.com/rails/rails/blob/v7.2.0/actionpack/CHANGELOG.md#L100-L102), [target source](https://github.com/rails/rails/blob/v8.1.0/actionpack/lib/action_dispatch/middleware/exception_wrapper.rb#L185-L199).
- **Application code:** [test.rb explicitly sets false](file:///home/user/workspace/repo/config/environments/test.rb#L30-L31); [authorization tests expect RecordNotFound to escape](file:///home/user/workspace/repo/test/controllers/activity_reports_controller_test.rb#L27-L35).
- **Consequence — inference:** Errors are converted into responses instead of propagating as before. Some assertions fail, while tests without response assertions could obscure an application error. The correction is mechanical (`:none`), but the **unfixed behavior change is silent**, hence high under this rubric; it is test-scoped, not a demonstrated production policy change.

### H11. Database reads may reconnect/retry rather than surface a transient failure

- **Before → after — changelog + upstream code:** 7.1 adds safe mid-request reconnection; 7.2 marks known-idempotent Arel SELECTs retryable, with later extensions to association/exists queries. Target defaults to one connection retry. [7.1 entry](https://github.com/rails/rails/blob/v7.1.0/activerecord/CHANGELOG.md#L1636-L1648), [7.2 entry](https://github.com/rails/rails/blob/v7.2.0/activerecord/CHANGELOG.md#L281-L288), [target retry logic](https://github.com/rails/rails/blob/v8.1.0/activerecord/lib/active_record/connection_adapters/abstract_adapter.rb).
- **Application code:** [Session user lookup](file:///home/user/workspace/repo/app/controllers/application_controller.rb#L7-L8) and [owned-note lookup](file:///home/user/workspace/repo/app/controllers/notes_controller.rb#L58-L60) use ordinary model SELECTs; [database configuration](file:///home/user/workspace/repo/config/database.yml#L17-L26) does not override retry behavior.
- **Consequence — inference:** During a connection interruption a read can take longer, reconnect, and succeed on a later database snapshot instead of immediately failing. Usually beneficial, but failure/latency assumptions and monitoring change. This is **not** evidence of automatic replay of arbitrary writes or whole business transactions; Rails limits retries to safe cases. Check deployed failover/timeout expectations; `connection_retries: 0` is the documented opt-out.

### H12. BigDecimal arithmetic also moves independently of the job serializer — review candidate

- **Before → after — changelog + upstream code:** Newly resolving BigDecimal 4.1.3 replaces this Ruby's default 3.1.5. Intervening changes fix division precision/rounding and replace division internals; target C source was compared with 3.1.5. [Versioned changelog](https://github.com/ruby/bigdecimal/blob/v4.1.3/CHANGES.md), [rounding PR #330](https://github.com/ruby/bigdecimal/pull/330).
- **Application code:** [User#reading_completion](file:///home/user/workspace/repo/app/models/user.rb#L53-L56) divides ready count by total then rounds to four places, and [the mailer consumes it](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L10).
- **Consequence — inference, unproven for this input domain:** Numeric fixes can silently change boundary results, so this is a high-risk numeric review candidate, **not a demonstrated changed completion percentage**. The bounded nonnegative ratio and final rounding may mask the upstream differences. Compare recurring fractions and four-place rounding boundaries if accepting this newly locked major version; do not confuse this with H4's independently established wire-format incompatibility. Removed `precs`, changed `divmod`, and BigMath APIs have no application call sites.

### H13. Trix dependency/CSS moves to 2.x while the browser JavaScript stays pinned to 1.x — compatibility review candidate

- **Before → after — changelog + upstream code:** Rails 7.1 moved bundled Trix to 2.x; 8.1 replaces the bundled dependency with `action_text-trix`, resolving 2.1.19 here. [7.1 entry](https://github.com/rails/rails/blob/v7.1.0/actiontext/CHANGELOG.md#L46-L48), [8.1 entry](https://github.com/rails/rails/blob/v8.1.0/actiontext/CHANGELOG.md#L53-L57). The new gem supplies Trix assets.
- **Application code:** [Layout explicitly loads `trix-1.3.5.js`](file:///home/user/workspace/repo/app/views/layouts/application.html.erb#L10-L14), [Action Text is imported separately](file:///home/user/workspace/repo/app/javascript/application.js#L1-L4), and [CSS requires the gem's `trix` stylesheet](file:///home/user/workspace/repo/app/assets/stylesheets/actiontext.css#L1-L7). [The editor persists Note#body](file:///home/user/workspace/repo/app/views/notes/_form.html.erb#L47-L50).
- **Consequence — inference, compatibility not executed:** The lockfile upgrade does **not** replace the vendored browser editor or deliver Trix 2 JavaScript fixes to it; it does change the gem-provided stylesheet and Rails integration alongside it. A 1.x-JS/2.x-CSS combination needs review. No specific incompatibility is established by source reading alone. Choosing to move the actual editor to 2.x adds a stored-rich-text/save-round-trip risk, so check links, attachments, imported HTML, and custom details/summary excerpts. Do not assume a successful Rails dependency update upgrades the browser editor.

## 3. Medium-risk changes

### M1. The configured built-in Sidekiq adapter is deprecated for removal in Rails 8.2

- **Before → after — changelog + upstream code:** 7.0 ships the adapter normally; 8.1 warns that it will be removed in 8.2 and recommends the Sidekiq-provided adapter in Sidekiq ≥7.3.3. The 8.1 built-in adapter still permits Sidekiq ≥4.1, so the current pin is not itself a dependency-resolution error. [8.1 entry](https://github.com/rails/rails/blob/v8.1.0/activejob/CHANGELOG.md#L19-L23), [adapter](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/queue_adapters/sidekiq_adapter.rb#L1-L37).
- **Application code:** [queue_adapter = :sidekiq](file:///home/user/workspace/repo/config/application.rb#L22-L24), [Sidekiq 6.5.12 pin](file:///home/user/workspace/repo/Gemfile#L34-L36).
- **Consequence — inference:** Rails 8.1 retains this path, but the next release removes it. Decide when to migrate the job adapter/Sidekiq stack; upgrading Sidekiq has its own Redis, dependencies, and queue compatibility review. Native [ExportJob](file:///home/user/workspace/repo/app/jobs/export_job.rb#L3-L10) does not depend on Active Job's adapter, although it shares Sidekiq. No claim that all runtime combinations were tested is made.

### M2. Newly resolved JSON 3 rejects provider responses previously accepted

- **Before → after — changelog + upstream code:** The existing Ruby default JSON 2.7.2 accepts duplicate object keys and comments; JSON 3 defaults reject them. JSON 3.1 also rejects non-ASCII BINARY strings during generation. Other removed JSON APIs were searched in the target Rails/held Sidekiq paths and application. [JSON 3.1.0 changelog](https://github.com/ruby/json/blob/v3.1.0/CHANGES.md#L5-L66).
- **Application code:** [Citation::Provider parses without compatibility options and converts ParserError into an enrichment failure](file:///home/user/workspace/repo/app/models/citation/provider.rb#L42-L59). [Note tags use JSON serialization](file:///home/user/workspace/repo/app/models/note.rb#L12). Sidekiq 6.5's source uses `JSON.parse` / `JSON.generate`; [the native export job uses simple ID/string-keyed options](file:///home/user/workspace/repo/app/jobs/export_job.rb#L1-L10).
- **Consequence — inference, input-dependent:** A response containing two `title` keys formerly used the last; the upgrade instead records an invalid-JSON failure. Decide whether the external contract must become strict or whether explicit, narrowly scoped compatibility options are required. No actual provider responses with this shape were observed. Ordinary generated tag arrays and normal job hashes do not establish a failure; audit unusual persisted JSON and string encodings, rather than assuming all JSON data breaks. No application dependency on the removed JSON convenience APIs was found.

## 4. Low-risk changes: direct mechanical corrections

Each line is **changelog + upstream-code evidence**, with the application consequence inferred statically; these should be caught by booting or focused tests once an upgrade is approved.

- **Keyword enum removed:** [Note status enum](file:///home/user/workspace/repo/app/models/note.rb#L10) must become `enum :status, { draft: 0, ready: 1 }, prefix: true`; other model enums are already positional ([8.0 removal](https://github.com/rails/rails/blob/v8.0.0/activerecord/CHANGELOG.md#L64-L66)).
- **Positional serializer removed:** [Note tags](file:///home/user/workspace/repo/app/models/note.rb#L12) must use `serialize :tags, coder: JSON`, preserving the existing JSON format, not changing it to YAML ([7.2 removal](https://github.com/rails/rails/blob/v7.2.0/activerecord/CHANGELOG.md#L421-L423)).
