Original → v21: what changed?

Rails 7.0.8.7 to 8.1.0. Accuracy = expected changes located in application code ÷ 23. The same rubric for every model and prompt.

OpenAI comparisons are complete. Claude evaluations are paused at the user’s request.

Accuracy here means “located,” not “actionable.” A change counts when the report describes it and names its affected application file. Impact and repair are not extra requirements. Astra low’s original mean is 90.4% located; the earlier 35.7% used a different, stricter measure. Historical grades remain unchanged in the source files.

How can the same reports score 35.7% and 90.4%?

The two graders ask different questions. The earlier score credits a finding only when impact, applicability, and recommendation are all supported. The coverage grader credits a change described and tied to its application file; it records factual accuracy separately. Neither percentage is an overall accuracy rate.

For Astra low, five reports × 23 expected findings = 115 report/finding pairs. The strict grader credits 41 pairs (35.7%); the coverage grader locates 104 (90.4%). Of the 64 pairs located but not actionable, 58 lose credit only because impact is “partial”; four have a partial recommendation and two an incorrect recommendation. One other pair passes strict grading but is only “named” under the coverage rubric, which requires a file. These are separate assessments, not perfectly nested scores.

Actual example, original run 1: the report identifies app/models/export.rb#generate and says, “Rails 7.1 removes its nonnumeric Enumerable/Array sum override. Ruby's zero identity is not a string concatenation identity. Replace with fragments.join (works on 7.0).” The strict grader marks impact partial because the report does not explicitly say the export worker raises TypeError. Applicability and repair are supported, and the coverage grader marks the finding located and accurate.

Read the comparison correctly
  • Original-plan actionability requires supported impact, applicability, and recommendation together. Missing an explicit consequence can lose the entire finding even when the affected code and repair are correct. This is not general accuracy or issue coverage. Risk reports instead measure located findings or matching risk levels.
  • The default scores complete planner reports, including linked artifacts for GPT. A short artifact link can score zero as final text even when the complete report exists. The Claude risk references use their retained graded final reports in both score-layer views; no separate primary-layer grade is available for those references.
  • The risk view overlays GPT v21 with Claude v19/v20 references. These use the same risk-grader instructions and labels, but different planner prompts and runtimes. The verified Claude risk runs are Opus high on v19/v20 and Opus low on v20; no Sonnet or Haiku risk runs were found in this retained set.
  • Original Claude scores use the October 12 hand assessments. GPT and the October 15 Claude risk reports use the automated Opus 5.5 high grader. Runtime, date, tools, and prompt versions differ. These are historical comparisons, not controlled model rankings. Opus-high original Rails was a development reference.
  • Averages exclude missing measurements, never replace them with zero. Haiku has incomplete report coverage. Cost-chart means use matched score and exact-cost runs. Lower-bound triangles are excluded. Table cost averages include every exact cost, including failed attempts.
  • Dollar amounts are standard API/list-price estimates, not bills. Original Claude uses retained October 13 rates; Claude risk reports use their October 15 receipt estimates; GPT uses October 19 rates. Operators, graders, orbs, unlogged helpers, and billing adjustments are excluded. Response time covers the whole main/planner workflow, not token speed.
Why Astra low looks worse on the original metric
The saved grader recognizes more expected issues and correct applicability/repair pairs in Astra-low reports, but awards fewer fully actionable findings because explicit application impact is often only partial. These diagnostics summarize the existing grades, not a regrade.
