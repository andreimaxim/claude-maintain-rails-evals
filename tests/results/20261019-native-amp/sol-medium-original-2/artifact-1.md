# Rails 7.0.8.7 → 8.1.0: Margin Notes upgrade assessment

## Decision and scope

**Not a Gemfile-only upgrade. Proceed in stages: 7.0 → 7.1 → 7.2 → 8.0 → 8.1, initially retaining `config.load_defaults 7.0`.** Ruby 3.3.6 already satisfies Rails 8.1's Ruby ≥3.2 requirement. No application files were changed by this assessment. This is a plan, not a completed upgrade.

The current lockfile really contains Rails 7.0.8.7, Sidekiq 6.5.12, redis 4.8.1, PostgreSQL/pg 1.6.0, Puma 5.6.9, Sprockets, importmap, and a vendored Trix 1.3.5. `config/application.rb:12` loads 7.0 defaults and selects Sidekiq; tests explicitly select `:test`. Do not replace these with a newly generated Rails 8 application's infrastructure.

**Evidence labels:** E = executed in isolated disposable application copies; S = versioned upstream/application source; P = validation still proposed. Runtime evidence is for the exact variants below, not for an implemented final upgrade.

## Required compatibility work (independent of adopting new defaults)

### 1. Action Text initializer prevents boot (E/S)
- **Affected:** `config/initializers/action_text.rb:3`; rich-text rendering in notes/imports and attachment rendering.
- **Change:** In 7.0, `ContentHelper.allowed_tags` inherits a populated list. In 7.1 onward it starts nil and the renderer computes its fallback. `allowed_tags += ...` therefore raises `NoMethodError`; reproduced on 8.1.
- **Recommendation:** Derive the inherited list from the configured sanitizer when nil, retain `ActionText::Attachment.tag_name`, `figure`, and `figcaption`, then add `details`/`summary`. Do not replace the list with just those two tags or broadly relax sanitization. Account for the chosen HTML4/HTML5 sanitizer before freezing a list; adopting HTML5 is a separate decision.
- **7.0 preparation:** A nil-aware fallback retaining existing populated tags works on 7.0 too. P: verify it on both runtimes with rich text, image/file attachments, malformed nesting, unsafe URL/event attributes, and collapsible excerpts. Existing request tests cover ordinary safe/unsafe HTML, not browser editing or parser differences.
- **Storage/rollback:** Do not rewrite rich-text bodies to fix rendering. Keep signed attachment references and original blobs. Preserve the signing key (see rollout).

### 2. Note enum and serialized tags APIs (E/S)
- **Affected:** `app/models/note.rb:10-12`.
- **Change:** Keyword-only enum declaration is removed in Rails 8.0; positional coder argument to `serialize` is removed in 7.2. Original target model loading fails at the enum.
- **Recommendation:** `enum :status, { draft: 0, ready: 1 }, prefix: true`; on Rails ≥7.1 use `serialize :tags, coder: JSON`. Preserve integer enum values and existing JSON-array text; no column/data conversion is required.
- **7.0 preparation:** The positional enum with `prefix:` works now (Citation and Export already use that style). **Do not move tags to `coder: JSON` on 7.0:** its `serialize` ignores that keyword when choosing the coder and would use YAML. Make the coder syntax change at the 7.1 step.
- **P validation:** Load old raw `[]` and multi-tag JSON rows, edit through the note request, reload, inspect raw stored JSON, then read that write with 7.0. Keep status filter/prefixed predicates working.

### 3. Highlight aliases a store accessor, not a database attribute (E/S)
- **Affected:** `app/models/note.rb:13-14`, note forms/strong parameters.
- **Change:** `color` is generated by `store_accessor :settings`; it is not a real column. Rails 7.2 removes support for `alias_attribute` targeting nonexistent attributes. Reproduced: 7.0 returns `pink`; 8.1 raises `ArgumentError`.
- **Recommendation:** Explicit `highlight_color` getter/setter delegating to `color`, or getter/setter method aliases after `store_accessor`. Keep the JSONB key `color` and external form field unchanged.
- **7.0 preparation:** Yes. P: existing highlighted row → form checked value → submit a different color → JSONB reload, plus invalid color rejection; preserve other settings keys. No data migration.

### 4. Routes, unbound form, association predicate, and exception-mode APIs (E/S)
- **Affected:** `config/routes.rb:18`; `app/views/notes/index.html.erb:12`; `app/controllers/notes_controller.rb:12`; `config/environments/test.rb:31`.
- **Changes/recommendations:**
  - Rails 8.1 removes multiple paths in one route declaration. Split `/notes` and `/journal` into separate `get` declarations, retaining `notes_path` and both GET endpoints.
  - Rails 8.0 rejects `form_with(model: nil, ...)`. Omit `model:` for this URL-based search form; do not invent a model.
  - Rails 7.2 removes plural-name fallback for singular associations. Replace `.where(notebooks: @notebook)` with `.where(notebook_id: @notebook.id)` (or the actual `notebook:` association). Target currently queries nonexistent `notes.notebooks`.
  - Rails 7.2 removes boolean `show_exceptions`. Use `:none` to preserve tests that expect raised authorization/not-found exceptions.
- **7.0 preparation:** First three changes work on 7.0. Change `show_exceptions` only once on ≥7.1: 7.0 treats a non-false symbol as enabled rather than preserving false's meaning.
- **P validation:** Both list URLs and canonical helper; GET search form query shape; an owned notebook filter excludes another owned notebook and foreign notes; authorization exceptions in tests and actual 404 responses in a production-like configuration. Existing request tests already discriminate most of these.

### 5. Provider configuration uses removed application secrets (E/S)
- **Affected:** `app/models/citation/provider.rb:13`; `config/secrets.yml`; `test/controllers/citation_enrichments_controller_test.rb:40-55,117-122`.
- **Change:** `Rails.application.secrets` deprecated 7.1, removed 7.2. Both provider execution and tests fail on target.
- **Recommendation:** Move these environment-backed settings to one explicit application configuration, e.g. `config.x.citation_provider`, keeping the URL/user/password environment contract and development-only defaults. Alternatively use encrypted credentials deliberately; do not silently require new production secrets. Update provider construction and test substitutions/fresh-process configuration checks together. Preserve strings exactly, including leading-zero usernames and punctuation in passwords.
- **7.0 preparation:** `config.x` or credentials are available now. No database change. Ensure web and worker deployments receive identical settings.
- **P validation:** Existing loopback-provider tests for exact Basic Auth, 503 retry, permanent refusal, and a fresh process; execute one real Sidekiq enrichment job with an isolated provider. Do not merely test enqueueing.

### 6. Enrichment retry option removed (S)
- **Affected:** `app/jobs/citation_enrichment_job.rb:7`.
- **Change:** `:exponentially_longer` is deprecated 7.1 and removed 7.2. The existing algorithm is polynomial, despite its name.
- **Recommendation:** On ≥7.1 rename to `:polynomially_longer`, retaining three attempts and jitter. Do not substitute a genuinely exponential algorithm. Faraday still retries a 503 once per attempt: maximum six provider calls remains the contract.
- **7.0 preparation:** Not this symbol rename: 7.0 does not recognize the new symbol. Perform at the 7.1 step.
- **P validation:** Force persistent 503; check three job attempts/six HTTP calls, delayed retries rather than immediate failure, and final persisted failure. Check one 401 causes one call. Pending/retrying jobs must execute under the new class without resetting execution counters.

### 7. Numeric reminder scheduling is no longer accepted (E/S)
- **Affected:** `app/models/note.rb:61`; imported and manually scheduled reminders, postponement.
- **Change:** Rails 7.2 removes numeric scheduled times. On 8.1 `wait_until: reminder_epoch` raises `undefined method utc for Integer` during serialization.
- **Recommendation:** Pass a Time such as `Time.at(reminder_epoch).utc`, not the integer, to `wait_until:`. Keep persisted epochs and stored Active Job IDs unchanged.
- **7.0 preparation:** Yes. P: exact non-round epoch, future and past times, replacement/reminder suppression, and refusing Redis enqueue while retaining the previous reminder. Existing reminder tests expose the basic scheduling failure.
- **Queue rollout:** Existing 7.0 Sidekiq scheduled items retain their outer schedule timestamp; 7.0's Active Job envelope has no `scheduled_at` field. Do not reschedule or regenerate IDs just because the new envelope includes ISO time. Cross-version actual scheduled/retry payload execution is still P.

### 8. Markdown string summation removed (E/S)
- **Affected:** `app/models/export.rb:42` (`fragments.sum`).
- **Change:** Rails 7.1 removes its string-aware Enumerable sum override; Ruby's numeric identity causes `TypeError`.
- **Recommendation:** Use `fragments.join` (or `sum("")`); `join` expresses concatenation directly.
- **7.0 preparation:** Yes, same output. P: compare exact Markdown with several asymmetric notes and an empty notebook; retain cancellation/progress/retry behavior and download authorization. Existing export tests expose the error. No stored-file conversion; completed exports should remain downloadable until their original expiry.

### 9. Import atomicity changes on nonlocal return (E/S; high data-integrity risk)
- **Affected:** `app/models/import.rb:50-60`, especially `return false` from inside `transaction` after a later row fails.
- **Change:** 7.0 rolls back this nonlocal exit; 7.2 removes that behavior and commits. A direct, non-test-transaction probe of a valid first row and invalid second row yielded:
  - 7.0: `[false, 0 imports, 0 notes]`.
  - 8.1 with 7.0 defaults: `[false, 1 import, 1 note: "Valid"]`.
- **Recommendation:** Explicitly raise `ActiveRecord::Rollback` for a rejected row, with an explicit false return after rollback. Do not rely on `return`, `break`, or the block returning false to roll back. Preserve validation errors for preview. Check every row and related citation/rich-text write stays in the same transaction.
- **7.0 preparation:** Yes; no data-format migration.
- **P validation:** Public `Import#apply` outside transactional test fixtures: first row valid/new citation, later row invalid; assert false and zero deltas in imports, notes, citations, and rich texts. Then valid batch commits all. Current request test covers row rejection but runs inside fixture transactions; do not use a green transactional test alone to establish real commit behavior. Audit any imports created during an unsuccessful rollout for partial batches; restoring code will not undo committed records.

### 10. Import preview annotations and receipt DOI silently disappear (E/S)
- **Affected:** `app/models/import.rb:38-41,68`; `app/views/imports/preview.html.erb:30,49-52`; citations use string primary key `doi`, not `id`.
- **Change A:** HashWithIndifferentAccess `stringify_keys` was a no-op for integer keys through 7.2; 8.0 removes that override. Preview stringifies source-line integers but later looks up integers: annotations vanish. Probe: `[[2], "annotation"]` becomes `[["2"], nil]`.
- **Recommendation A:** Remove the unnecessary `.stringify_keys` in this view; use integer source lines consistently. Works on 7.0.
- **Change B:** 7.2 removes `read_attribute(:id)` fallback for a custom primary key. `citation[:id]` becomes nil; direct receipt probe changes `Cited,10.1000/probe` to `Cited,`.
- **Recommendation B:** Read `citation.doi` explicitly. Works on 7.0; no DOI normalization or database-key migration.
- **P validation:** Preview annotations on distinct source lines including a quoted multiline row; assert literal markup is escaped, not lost. Download receipt and check exact DOI values shared by multiple rows. Existing preview tests fail early and can mask the subsequent receipt/atomicity failures.

### 11. Digest serialization changes both behavior and rollback compatibility (E/S)
- **Affected:** `app/models/user.rb:34-56`; `app/jobs/digest_job.rb`; `app/mailers/digest_mailer.rb:8-10`; Redis daily reservation keys.
- **Time-zone change:** New TimeWithZone serialization preserves the originating IANA zone, independently of defaults. The app currently relies on deserialization in UTC, but the mailer uses `requested_at.to_date/all_day`. At `2026-10-05 03:30Z` (Eastern local October 4, 23:30), the subject changes October 5 → October 4, while reservation remains October 5 UTC. Existing digest test catches this particular boundary.
- **Recommendation:** Preserve the documented UTC digest contract explicitly: normalize requested time to UTC in the mailer before choosing its day/window, and enqueue a UTC Time rather than a reader-zone TimeWithZone. Retain the existing UTC reservation key. Both preparations work on 7.0. If local-day digests are desired, that is a separate product change requiring coordinated reservation semantics, not a framework-default adoption.
- **Decimal change:** New Active Job uses tagged BigDecimal serialization. Old 7.0 JSON queues contain a decimal string; new workers read those. New tagged arguments are **not readable by old 7.0 workers**: reproduced `ActiveJob::DeserializationError`, unknown `BigDecimalSerializer`. Retaining `load_defaults 7.0` does not prevent it. Test adapter does not model the queue JSON round trip.
- **Recommendation:** Before upgrading producers, serialize completion intentionally as `reading_completion.to_s("F")`; this preserves the existing queue string contract and works on 7.0. Current `BigDecimal(params[:completion])` accepts both new BigDecimals and old strings, so no mailer decimal rewrite is inherently required. Alternatively explicitly upgrade all consumers first and drain tagged work before rollback; that is more operationally fragile.
- **P validation:** Actual Sidekiq/Redis JSON round trips, old producer/new consumer and new producer/old consumer, with 2/3 completion (not 0 or 1), near UTC/local midnight and DST. Assert subject, exact included/excluded notes, percentage, and one reservation per UTC day. Test legacy payloads already queued before prep.

### 12. Reminder DST preview semantics change in 8.1 (E/S)
- **Affected:** `app/models/note.rb:43-44`; `app/views/notes/_reminder.html.erb:19`; existing reminder test expectation.
- **Change:** 8.1 `TimeWithZone#to_time` always preserves the named zone. Adding 86,400 elapsed seconds now reflects the destination DST offset. Probe for Eastern October 31 2026 09:00:
  - 7.0 preview: `2026-11-01T09:00:00-04:00`.
  - 8.1 preview: `2026-11-01T08:00:00-05:00`.
  - Both represent epoch `1793538000`; scheduled instant is unchanged.
- **Recommendation:** Deliberately adopt the correct reader-zone display, preferably express it explicitly with zone-aware elapsed-second arithmetic on both versions, then update the old fixed-offset test/documentation. If fixed-offset display is intentional, construct it explicitly; don't rely on the removed configuration behavior.
- **7.0 preparation:** Zone-aware elapsed arithmetic is available now. P: spring forward and fall back, asserting both epoch +86,400 and rendered local offset/time. Never replace 24 elapsed hours with “same wall time tomorrow” without approval. No epoch migration.

### 13. Newly resolved JSON 3 breaks exact Rails 8.1.0 (E/S; environment-dependent dependency blocker)
- **Affected:** Gemfile/lockfile; JSONB settings, serialized attributes, and sessions.
- **Observation:** Conservative `bundle update rails` resolves JSON 3.1.0 here. Rails 8.1.0's `ActiveSupport::JSON.decode` calls `JSON.parse(json, options)`; this JSON version only accepts keyword options. Many requests fail with wrong-number-of-arguments, not an application query bug. Backtrace retained.
- **Recommendation:** Constrain JSON to a tested compatible 2.x release while assessing exact Rails 8.1.0, and lock the resolution. Experimental pin 2.7.2 removes this blocker. A different Rails patch may resolve the API incompatibility, but was not tested here and is outside the requested exact target.
- **7.0 preparation:** This experiment's 2.7.2 is also the baseline default JSON version. Adding the tested pin is compatible now. P: JSONB load/update, tags, session sign-in, provider JSON parsing, and argument round trips on the final lockfile. Do not freeze all transitive dependencies blindly.

## Rollout and rollback sequence

1. **On 7.0:** land backward-compatible behavior-preserving preparations above: explicit import rollback, DOI read, integer preview keys, highlight delegation, enum shape, string join, route split, URL-only form, explicit notebook FK predicate, provider config migration, Time reminder argument, UTC/string digest wire contract. Decide DST display intentionally. Keep original stored formats and IDs. Run baseline/request tests plus nontransactional import and real queue probes.
2. **7.1:** change JSON coder keyword, retry symbol, symbolic exception mode, and optionally make preferences explicitly YAML. Merge `app:update` selectively; don't overwrite current config or adopt all generated defaults. Capture deprecations, eager loading, production-like boot, asset compilation and final dependency lock. Repeat through 7.2, 8.0 and exact 8.1.0, holding framework defaults unless each is separately qualified. Keep JSON version compatible.
3. **Queue cutover:** Inventory default queue, retry/dead sets, and scheduled set—not only ready jobs. Long-future reminder jobs cannot simply be “drained” promptly. After compatible producer preparations, upgrade consumers before producers. Verify representative old reminder/enrichment envelopes execute on new workers with original IDs/counters; native ExportJob class/signature must remain loadable. Include Active Storage analysis/purge jobs if any are queued. Keep queue name/Redis URL unchanged in the real deployment; this assessment's isolated URLs are only for experiments.
4. **Mixed operation:** Keep old message/cache writing formats and same signing secret until all consumers/web nodes and rollback path support new formats. Keep old asset digests available for open tabs during deployment. Watch failed/deserialization jobs, partial imports, pending citation states, reminder delivery, digest dates, and export errors. Redis reservation keys must continue to mean UTC dates and retain their two-day expiry.
5. **Rollback:** Stop new producers before swapping workers; inspect newly tagged BigDecimal jobs and retry/scheduled sets. With UTC/string producer preparation, the specific new serializer hazard is avoided; without it, drain/transform under a reviewed procedure before old workers resume. Do not blindly flush Redis (would lose reminders and deduplication reservations). Do not clear active-job IDs or reset completed/sent records. Leave already generated files and unchanged JSON/YAML records readable; rollback does not undo partial committed imports or already sent emails. After adopting new signature formats, a code rollback alone may be insufficient: old consumers cannot necessarily read newly issued references, including persisted rich-text SGIDs. Keep compatibility writing options through the rollback window.
6. **After stable runtime upgrade:** adopt defaults one by one using the matrix, then move `load_defaults`. Keep database changes additive if anything extra is introduced; this assessment identifies no necessary application-table migration. Rails 8.1 alphabetizes schema columns: review as dump churn, not a reason to rebuild tables. On dev/test preserve `tmp/development_secret.txt` as `tmp/local_secret.txt` during 7.1 transition if old local sessions/attachment signatures matter; this does not substitute for production key management.
