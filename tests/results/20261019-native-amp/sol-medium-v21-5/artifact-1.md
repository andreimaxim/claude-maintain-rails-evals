# Rails 7.0.8.7 → 8.1.0: application-specific upgrade risk

## Application facts and assessment boundary

- **Code:** Ruby is pinned to 3.3.6 and Rails to 7.0.8.7 ([Gemfile:4–8](file:///home/user/workspace/repo/Gemfile#L4-L8)). Rails 8.1.0 requires Ruby ≥ 3.2, so the configured Ruby meets its requirement ([target gemspec](https://github.com/rails/rails/blob/v8.1.0/rails.gemspec)).
- **Code:** This assessment assumes **only the gem requirement changes**, retaining `config.load_defaults 7.0` ([application.rb:12–24](file:///home/user/workspace/repo/config/application.rb#L12-L24)). A section below separately identifies consequential opt-in defaults. A version bump does not automatically adopt Rails 8.1 defaults or regenerate the application.

The deployed PostgreSQL version was not inspected. Both compared adapters check for PostgreSQL ≥ 9.3; there is no newly raised PostgreSQL minimum in this comparison.
- **Code:** Server-rendered ERB HTML, Sprockets, importmap and Turbo; notes have Action Text bodies and local Disk attachments, with no image processor ([Gemfile:10–26](file:///home/user/workspace/repo/Gemfile#L10-L26), [storage.yml](file:///home/user/workspace/repo/config/storage.yml), [blob partial:1–13](file:///home/user/workspace/repo/app/views/active_storage/blobs/_blob.html.erb#L1-L13)). Exports use native Sidekiq jobs ([Gemfile:34–36](file:///home/user/workspace/repo/Gemfile#L34-L36), [application.rb:24](file:///home/user/workspace/repo/config/application.rb#L24), [test.rb:37](file:///home/user/workspace/repo/config/environments/test.rb#L37), [ExportJob](file:///home/user/workspace/repo/app/jobs/export_job.rb#L1-L12)). Reminders can remain scheduled across deployments; no actual Redis queues were read.
- **Code:** Production enables fragment caching without overriding Rails' FileStore default; development uses MemoryStore when enabled, otherwise NullStore; tests use NullStore ([production.rb:17–19](file:///home/user/workspace/repo/config/environments/production.rb#L17-L19), [development.rb:23–36](file:///home/user/workspace/repo/config/environments/development.rb#L23-L36), [test.rb:25–28](file:///home/user/workspace/repo/config/environments/test.rb#L25-L28)). **Method/evidence labels:** **Changelog** means a gem release entry; **Code** means compared upstream source or application source; **Inference** means the application consequence derived from that source, not a runtime reproduction. Ratings concern impact, not likelihood. No application boot, tests, database/Redis access, new-gem installation, or application edits were performed.

**Dependency resolution:** On 2026-10-19, I copied `Gemfile` and `Gemfile.lock` to a temporary directory, changed only the Rails requirement there, and ran `bundle lock --update rails` using Bundler 2.5.22. It succeeded. All 13 Rails gems move together to 8.1.0. Rack remains **2.2.24** because the pinned Sidekiq requires Rack ~> 2.0; neither Sidekiq, Redis, Puma nor Faraday changes. Do not assume Rack 3 migration requirements apply here.

New lock entries: `action_text-trix 2.1.19`, `bigdecimal 4.1.3`, `drb 2.2.3`, `json 3.1.0`, `rack-session 1.0.2`, `rackup 1.0.1`, `securerandom 0.4.1`, `uri 1.1.2`, `useragent 0.16.11`, `webrick 1.9.2`. The unlocked Ruby libraries previously came from Ruby 3.3.6 here: JSON 2.7.2, BigDecimal 3.1.5, DRb 2.2.0, SecureRandom 0.3.1, URI 0.13.1. Those baselines can differ on another Ruby installation.

## High-risk changes

### H1. A failed CSV import can now commit a partial batch

**Before — Code:** Rails 7.0 rolls back a transaction that has written data and exits through a non-local return. `Import#apply` saves the import, then saves rows, returning `false` directly from inside the transaction when a row fails ([import.rb:50–60](file:///home/user/workspace/repo/app/models/import.rb#L50-L60)).

**After — Changelog + Code:** Rails restored commit-on-`return`/`break`/`throw`; by 8.1 the legacy rollback option is removed. The 8.1 transaction manager commits in `ensure` when there was no exception. Sources: [PR #48600](https://github.com/rails/rails/pull/48600), [8.0 removal entry](https://github.com/rails/rails/blob/v8.0.0/activerecord/CHANGELOG.md), [target transaction manager](https://github.com/rails/rails/blob/v8.1.0/activerecord/lib/active_record/connection_adapters/abstract/transaction.rb).

**Consequence — Inference:** A valid first row followed by an invalid row can leave the import, earlier notes, rich text and citations committed while the controller reports failure. This violates the all-or-nothing contract. Review explicit rollback/exception control flow before upgrading; an ordinary `false` result is not a rollback. The existing [invalid-import test:48–73](file:///home/user/workspace/repo/test/controllers/imports_controller_test.rb#L48-L73) is particularly valuable once an upgrade is authorized.

### H2. Digest job dates change from UTC to the reader's zone

**Before — Code:** The 7.0.8.7 `TimeWithZoneSerializer` keeps the instant/offset but deserializes with the job's current zone. This app constructs a reader-zoned time without changing `Time.zone`, so the worker sees UTC.

**After — Changelog + Code:** The serializer writes an additional `time_zone` and restores it; old payloads without it still use the current zone. Source: [PR #50240, including compatibility discussion](https://github.com/rails/rails/pull/50240), [target serializer](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/serializers/time_with_zone_serializer.rb). Although the PR was backported, the exact **7.0.8.7** source does not contain this behavior.

**Use/consequence — Code + Inference:** [User:34–41](file:///home/user/workspace/repo/app/models/user.rb#L34-L41) reserves a Redis key for a **UTC day**, then queues the zoned time. [DigestMailer:7–12](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L7-L12) uses `requested_at.to_date` and `requested_at.all_day`. New payloads therefore produce reader-local date headings and note windows, while reservation days remain UTC. Near midnight, content and deduplication boundaries diverge. Old and new payloads can produce different digests even on the same upgraded worker. Choose the intended content day explicitly; do not treat this as a formatting-only fix.

### H3. BigDecimal job arguments change wire format across old/new workers

**Before — Changelog + Code:** BigDecimal is treated as a primitive; Sidekiq JSON turns it into a string.

**After — Changelog + Code:** Active Job uses a tagged `BigDecimalSerializer` and reconstructs a BigDecimal. The transitional opt-out was removed; retaining 7.0 defaults does not preserve the old writer. Sources: [7.1 introduction and rollout warning](https://github.com/rails/rails/blob/v7.1.0/activejob/CHANGELOG.md), [7.2 removal of primitive behavior](https://github.com/rails/rails/blob/v7.2.0/activejob/CHANGELOG.md), [target serializer](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/serializers/big_decimal_serializer.rb).

**Use/consequence — Code + Inference:** [User:41,54–56](file:///home/user/workspace/repo/app/models/user.rb#L34-L56) queues completion as BigDecimal. Rails 7.0 workers cannot resolve the new serializer, so a rolling deployment or rollback with new digest payloads still queued can fail deserialization. The mailer's `BigDecimal(params[:completion])` already accommodates the restored type; the primary risk is deployment compatibility, not that conversion. Plan consumer-first compatibility or queue isolation/draining, including retries, rather than assuming a successful boot proves safety.

### H4. Import preview annotations silently disappear

**Before — Changelog + Code:** `HashWithIndifferentAccess#stringify_keys` effectively duplicates the hash, leaving integer keys unchanged.

**After — Changelog + Code:** It stringifies integer keys too ([8.0 changelog](https://github.com/rails/rails/blob/v8.0.0/activesupport/CHANGELOG.md), [target hash implementation](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/hash_with_indifferent_access.rb)).

**Use/consequence — Code + Inference:** [Import:37–41](file:///home/user/workspace/repo/app/models/import.rb#L37-L41) keys annotations by integer source line. The [preview:22,42–44](file:///home/user/workspace/repo/app/views/imports/preview.html.erb#L22-L44) stringifies the keys, then still looks up `annotations[row.line]`. Integer lookup no longer finds the string key. Annotations remain stored on imported notes, but disappear from the preview without an error, including the preview a reader checks before applying.

### H5. CSV receipts lose DOI values

**Before — Code:** `read_attribute(:id)`, including `record[:id]`, maps to a model's custom primary key.

**After — Changelog + Code:** That remapping is removed; `id` remains the model-level primary-key reader, but `[:id]` reads the literal attribute ([7.2 removal entry](https://github.com/rails/rails/blob/v7.2.0/activerecord/CHANGELOG.md), [target reader](https://github.com/rails/rails/blob/v8.1.0/activerecord/lib/active_record/attribute_methods/read.rb)).

**Use/consequence — Code + Inference:** [Import#receipt:63–69](file:///home/user/workspace/repo/app/models/import.rb#L63-L69) exports `citation[:id]`; [schema:55–62](file:///home/user/workspace/repo/db/schema.rb#L55-L62) makes `doi` the primary key and defines no `id` column. The missing literal attribute reads as nil, leaving the CSV DOI field blank rather than exporting the DOI. Use an explicit DOI or primary-key reader in a future fix; this is high because the externally consumed data changes silently, despite the fix being small.

### H6. Reminder postponement changes offset/wall-clock presentation across DST

**Before — Code:** Under 7.0 defaults, `TimeWithZone#to_time` preserves a fixed UTC offset.

**After — Changelog + Code:** Rails 8 introduced preservation of the named zone; 8.1 removes the old behavior and `TimeWithZone#to_time` always uses `getlocal(time_zone)` ([8.0 changelog](https://github.com/rails/rails/blob/v8.0.0/activesupport/CHANGELOG.md), [8.1 removal entry](https://github.com/rails/rails/blob/v8.1.0/activesupport/CHANGELOG.md), [target method](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/time_with_zone.rb)).

**Use/consequence — Code + Inference:** [Note:40–44,71–72](file:///home/user/workspace/repo/app/models/note.rb#L40-L72) adds 86,400 seconds after `to_time`; the [reminder view:16–20](file:///home/user/workspace/repo/app/views/notes/_reminder.html.erb#L16-L20) displays it. The elapsed instant is still 24 hours later, but the new Time tracks DST and displays the new offset rather than the previous fixed offset. Expect changed preview times around both DST boundaries; do not “fix” this by assuming it changes the intended elapsed delay.

### H7. Expired export fragments can be written without a TTL

**Before — Code:** Cache options accepted a negative `expires_in`, giving an already-expired entry.

**After — Changelog + Code:** Negative TTLs are removed from options. With retained 7.0 defaults Rails logs/reports the invalid expiration instead of raising, then writes using remaining/default options ([7.1 changelog](https://github.com/rails/rails/blob/v7.1.0/activesupport/CHANGELOG.md), [target `merged_options`](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/cache.rb)).

**Use/consequence — Code + Inference:** The [export partial:25–36](file:///home/user/workspace/repo/app/views/exports/_export.html.erb#L25-L36) passes `export.expires_at - Time.current` even for already expired completed exports. That can become a persistent expired-status fragment under its unchanged key. The normal expired label is still correct, and the [download controller:5–15](file:///home/user/workspace/repo/app/controllers/export_downloads_controller.rb#L5-L15) independently checks ownership/deadline, so this is **not evidence of an authorization bypass**. Nevertheless the cache lifetime contract silently changes. Cache only while the deadline is positive, or make an explicit expiry policy. Adopting 7.1 defaults changes this same case into an exception instead.

### H8. Plain-text exports and previews change for existing HTML

**Before/after — Code:** Compared source shows `to_plain_text` now discards `script`/`style` node contents and ordered-list numbering counts element siblings rather than all child nodes. The converter also becomes iterative for deep input. These details are not fully enumerated in the release changelogs ([released-source comparison](https://github.com/rails/rails/compare/v7.0.8.7...v8.1.0), [target converter](https://github.com/rails/rails/blob/v8.1.0/actiontext/lib/action_text/plain_text_conversion.rb)).

**Use/consequence — Code + Inference:** [CSV import:101–106](file:///home/user/workspace/repo/app/models/import.rb#L101-L106) accepts body HTML. [Export:66–81](file:///home/user/workspace/repo/app/models/export.rb#L66-L81) persists the plain-text conversion as a Markdown attachment, and [preview:56–58](file:///home/user/workspace/repo/app/views/imports/preview.html.erb#L56-L58) shows it. Existing imported HTML containing those nodes, or formatted lists with intervening whitespace nodes, can produce different text on regeneration. Existing completed files are not rewritten automatically. Stored content was not inspected; this is a source-confirmed change with data-dependent exposure, not a claim that such notes currently exist.

### H9. Blob metadata updates now touch owning records

**Before/after — Changelog + Code:** Rails adds `Blob.after_update :touch_attachments`; touching each attachment propagates to its owning record, including Action Text's `RichText`, whose parent association also uses `touch: true` ([7.1 changelog](https://github.com/rails/rails/blob/v7.1.0/activestorage/CHANGELOG.md), [target blob](https://github.com/rails/rails/blob/v8.1.0/activestorage/app/models/active_storage/blob.rb), [target RichText](https://github.com/rails/rails/blob/v8.1.0/actiontext/app/models/action_text/rich_text.rb)).

**Use/consequence — Code + Inference:** Notes embed blobs ([Note:8,95–98](file:///home/user/workspace/repo/app/models/note.rb#L8-L98)); digests select notes by `updated_at` ([DigestMailer:9](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L9)). Analysis/metadata updates can now advance note timestamps and make an old note qualify for a day's digest without a reader edit. Export-file updates can also invalidate the export fragment. With no image processor, common image analysis may use the null analyzer synchronously; not every attachment necessarily causes a later job or a changed digest. Review actual metadata-update timing, especially other media types, before attributing a particular digest difference to this change.

### H10. Local signing-secret selection can invalidate sessions and attachment signatures

**Before/after — Changelog + Code:** Rails 7.0 generates a local key in `tmp/development_secret.txt`. Rails 7.1 changes the path to `tmp/local_secret.txt`; target 8.1 also prefers `SECRET_KEY_BASE` or credentials locally when present ([upgrade guide](https://github.com/rails/rails/blob/v8.1.0/guides/source/upgrading_ruby_on_rails.md), [target secret selection](https://github.com/rails/rails/blob/v8.1.0/railties/lib/rails/application/configuration.rb)).

**Use/consequence — Code + Inference:** The app uses [cookie sessions](file:///home/user/workspace/repo/app/controllers/application_controller.rb#L7-L18) and [signed blob URLs](file:///home/user/workspace/repo/app/views/active_storage/blobs/_blob.html.erb#L3-L11), plus stored attachment SGIDs inside Action Text. If selection changes the key, old local sessions/signatures fail; persisted local rich text may show missing attachments. Preserve the same signing key where continuity matters. This is conditional: no secret files or values were inspected, so a key change in this workspace or production is **not established**. Production is not affected by the local filename rename.

### H11. The resolved JSON upgrade tightens accepted provider/stored input

**Before/after — Dependency changelog + Code:** JSON 2.7.2 → 3.1.0 now rejects duplicate object keys and JavaScript comments by default, rejects more malformed Unicode/escapes, removes `create_additions`, and errors on unknown options. Generation also rejects non-ASCII BINARY strings ([JSON 3.1.0 history](https://github.com/ruby/json/blob/v3.1.0/CHANGES.md)).

**Use/consequence — Code + Inference:** [Citation::Provider:42–52](file:///home/user/workspace/repo/app/models/citation/provider.rb#L42-L52) parses provider responses, so a formerly accepted duplicate-title/URL or commented response now records a provider error instead. JSON also backs [tags/settings](file:///home/user/workspace/repo/app/models/note.rb#L12-L14), Sidekiq payloads and Active Storage metadata. Valid ordinary app-generated JSON has no demonstrated problem; existing nonstandard stored JSON could become unreadable, and a generation failure could prevent persistence/enqueue. No such payload was observed. Review real provider examples and stored data rather than assuming the new dependency is merely packaging.

### H12. BigDecimal division and rounding change underneath completion calculations

**Before/after — Dependency changelog + Code:** The resolved dependency replaces Ruby's BigDecimal 3.1.5 with 4.1.3. Its intervening history includes division precision/rounding fixes and a new division implementation ([history](https://github.com/ruby/bigdecimal/blob/v4.1.3/CHANGES.md), [rounding PR #330](https://github.com/ruby/bigdecimal/pull/330)).

**Use/consequence — Code + Inference:** [User:54–56](file:///home/user/workspace/repo/app/models/user.rb#L54-L56) divides ready-note counts by total counts and rounds to four decimals; the [digest template:14](file:///home/user/workspace/repo/app/views/digest_mailer/daily_digest.text.erb#L14) displays the percentage. Numeric fixes are relevant because a changed quotient/rounding result would silently change that output. **Exposure is uncertain:** I did not establish a changed result for this particular bounded ratio; review rounding-boundary ratios before treating this as an observed regression. Removed `precs`, changed `divmod` return types and BigMath functions have no application callers. H3 is the independently confirmed job-format hazard.

## Medium-risk changes

### M1. Citation-provider configuration loses `Rails.application.secrets`

**Before — Code:** The provider defaults to `Rails.application.secrets.citation_provider.to_h` ([provider.rb:13–15](file:///home/user/workspace/repo/app/models/citation/provider.rb#L13-L15)); request tests also read/mutate that object ([citation tests:117–122](file:///home/user/workspace/repo/test/controllers/citation_enrichments_controller_test.rb#L117-L122)).

**After — Changelog + Code:** Deprecated in 7.1, `Rails.application.secrets` is removed in 7.2 ([removal entry](https://github.com/rails/rails/blob/v7.2.0/railties/CHANGELOG.md)). Calling the default provider initializer raises instead of loading the YAML-backed configuration.

**Consequence — Inference:** Enrichment jobs can fail with an unexpected error and leave citations pending while Sidekiq retries. Choose how to migrate the configuration: credentials, environment-backed application configuration, or an explicit `config_for` file. Preserve symbol-key behavior and test overrides. Merely copying the old YAML file into the deployment does not restore the API.

### M2. The Sidekiq adapter is deprecated for removal in the next release

**Before/after — Changelog + Code:** The built-in adapter remains usable with the pinned 6.5.12, but 8.1 warns that it will be removed in **Rails 8.2**; Rails directs users to Sidekiq ≥ 7.3.3's own adapter ([8.1 entry](https://github.com/rails/rails/blob/v8.1.0/activejob/CHANGELOG.md), [adapter's exact warning](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/queue_adapters/sidekiq_adapter.rb)).

**Use/consequence — Code + Inference:** [application.rb:24](file:///home/user/workspace/repo/config/application.rb#L24) selects this adapter, covering citations, digests, reminders and framework storage jobs. The requested Rails bump does **not** upgrade Sidekiq/Redis. Decide whether to retain the deprecated adapter for this release or undertake a separately scoped Sidekiq migration; the latter has its own Redis/client/native-job implications. Production suppresses Rails deprecation reporting ([production.rb:75–76](file:///home/user/workspace/repo/config/environments/production.rb#L75-L76)), so do not rely on production logs to flag the next-release blocker.

- **High, conditional — export conditional responses:** 8.0 defaults enable `strict_freshness`, preferring ETag when both request validators exist; old behavior requires both to match. - **High, conditional — editor/content normalization:** Rails now obtains Trix ≥ 2.1.15 from `action_text-trix` (resolved 2.1.19), with modern client sanitization/DOMPurify. No incompatibility of this exact mix was runtime-proven. **Changelog + Code + Inference:** [8.1 entry](https://github.com/rails/rails/blob/v8.1.0/actiontext/CHANGELOG.md), [Trix 2.1.19 release](https://github.com/basecamp/trix/releases/tag/v2.1.19).
