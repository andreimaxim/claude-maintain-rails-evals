# Margin Notes: Rails 7.0.8.7 → 8.1.0 upgrade assessment

**Recommendation: proceed as a staged compatibility upgrade, not a Gemfile-only deployment and not a simultaneous `load_defaults 8.1` change.** Ruby 3.3.6 already satisfies Rails 8.1.0's Ruby ≥ 3.2 requirement. Retain PostgreSQL, Sprockets/importmap, Sidekiq and Rails 7.0 defaults initially. Solid Queue, Solid Cache, Propshaft, Kamal and the generated authentication system are not upgrade requirements.

The working application's tracked files, dependencies, databases, Redis queues and files were not changed. All execution used disposable copies and separately named resources. This is a plan with experimental candidate patches, not an implemented or deployable upgrade. Experiments were performed October 19, 2026 against the checkout identified in the evidence README.

## Evidence and limits

- **Source:** application models/controllers/views/configuration, schema, migrations and tests; upstream Rails tags **v7.0.8.7, v7.1.0, v7.2.0, v8.0.0, v8.1.0**, not moving stable branches. The versioned [upgrade guide](https://guides.rubyonrails.org/v8.1.0/upgrading_ruby_on_rails.html) recommends minor-by-minor upgrades and independent adoption of defaults. Release-note summaries are supplemented below with implementation and changelog evidence.
- **Executed baseline:** original Rails 7.0.8.7, Ruby 3.3.6, `bin/rails test`: **46 runs, 325 assertions, zero failures/errors/skips**.
- **Executed unchanged target:** Rails 8.1.0 resolves, but boot fails at `config/initializers/action_text.rb:3` (`nil + ...`). After the initializer correction, eager loading fails on Note's old enum declaration.
- **Executed limited target variant:** with initializer/enum/serialize/alias/routes/test-exception corrections and JSON < 3, tests report **46 runs, 174 assertions, 3 failures and 15 errors**. These exposed real application incompatibilities, not a successful upgrade.
- **Executed final experimental compatibility candidates:** with the changes recorded in `variants/current.patch` and `variants/target.patch`, the current-version suite passes **46/325**, the target suite passes **46/340**, and target `zeitwerk:check` and **test-environment** `assets:precompile` succeed. Framework assertion counts differ; no expected business outputs were relaxed. The citation test harness was migrated from the removed secrets API. No new permanent tests were added to the working application.
- **Executed outside the test transaction wrapper:** an invalid second CSV row leaves one Import, Note, Citation and rich-text row saved on target, versus none on current. Candidate rollback handling leaves zero rows in both versions.
- **Executed serialization checks:** actual JSON round trips (not just Active Job's in-memory test adapter), old/new payload reads, and full DigestJob envelope deserialization in both versions. These are not an executed Sidekiq worker deployment.
- **Not executed:** intermediate Rails applications, browser/system tests, full `load_defaults 8.1` suite, production-mode boot/precompile, real workers consuming mixed queues, Sidekiq 7, real mail delivery, production credentials/secrets, or a production-data inventory. No production data was accessed.

## 1. Required compatibility changes

Each item distinguishes a preparation possible on 7.0 from a change that must wait until 7.1 or later. “Executed” refers only to the isolated variants, not the working application. All other validation below is proposed.

### 1.1 Rich-text initialization: boot blocker from 7.1

**Code:** [initializer](file:///home/user/workspace/repo/config/initializers/action_text.rb#L1-L3), Note rich bodies, CSV HTML imports, blob partial and rich-text rendering tests.

**Change/applicability:** Action Text's allowed-tag and attribute accessors now start as nil; their inherited allowlists are resolved at rendering. This applies even with `load_defaults 7.0`. The current `allowed_tags += ...` crashes. [7.1 tagged changelog](https://github.com/rails/rails/blob/v7.1.0/actiontext/CHANGELOG.md), [8.1 helper implementation](https://github.com/rails/rails/blob/v8.1.0/actiontext/app/helpers/action_text/content_helper.rb).

**Recommendation:** build the extension from the effective inherited allowlist, including Action Text attachment/figure tags, then add details/summary. Do not replace the default with only those two tags or solve it with `Array(nil)`, which would discard safe defaults. Candidate uses the current configured sanitizer's class allowlist and the framework attachment tags when the accessor is nil. If adopting HTML5 later, resolve the allowlist after that vendor is configured.

**Current-version preparation:** yes; candidate fallback also works with 7.0's already populated allowlist. Executed existing tests retain details/summary, reject scripts/unsafe links and render attachments on both versions.

**Validation still needed:** stored complex/malformed HTML, content attachments and browser edit/save round trips; verify links, captions, SGIDs and custom collapsible content. Existing render tests do not establish editor preservation.

### 1.2 Note declarations: enum, JSON serialization and virtual alias

**Code:** [Note lines 10–14](file:///home/user/workspace/repo/app/models/note.rb#L10-L14), note form and controller parameters.

- **Enum:** change to `enum :status, { draft: 0, ready: 1 }, prefix: true`. Keep integer mappings and generated `status_ready` names unchanged. Old keyword declaration was removed in Rails 8.0. **Works on 7.0; executed** in candidates. Validate filtering, edit/create and persisted draft/ready values. [8.0 AR changelog](https://github.com/rails/rails/blob/v8.0.0/activerecord/CHANGELOG.md).
- **Tags JSON:** change `serialize :tags, JSON` to `serialize :tags, coder: JSON` at the **7.1 step**, keeping JSON on the existing text column. Rails 7.2 rejects aliases to nonexistent columns; merely retaining defaults does not help. **Works on 7.0; executed**. Test yellow → green persists under `settings["color"]`, reloads into the form, and leaves tags/other settings unchanged. Source: [7.2 removals](https://github.com/rails/rails/blob/v7.2.0/activerecord/CHANGELOG.md), [8.1 alias generation](https://github.com/rails/rails/blob/v8.1.0/activerecord/lib/active_record/attribute_methods.rb). ### 1.4 CSV import atomicity: actual stored-data regression

**Code:** [Import#apply](file:///home/user/workspace/repo/app/models/import.rb#L50-L61), [create response](file:///home/user/workspace/repo/app/controllers/imports_controller.rb#L11-L20).

**Applicability:** at least one row has saved and a later `row.note.save` returns false. The method returns nonlocally from inside `transaction`. Rails 7.0 rolls back; Rails 7.2+ commits on this path regardless of retained 7.0 defaults. In 7.1 this behavior is configurable/new-default-dependent; Rails 8.0 removes the switch. [7.1 explanation](https://github.com/rails/rails/blob/v7.1.0/activerecord/CHANGELOG.md), [7.2 transaction implementation](https://github.com/rails/rails/blob/v7.2.0/activerecord/lib/active_record/connection_adapters/abstract/transaction.rb).

**Recommendation:** explicitly raise `ActiveRecord::Rollback` on an unsuccessful row save, return true only from a completed transaction, and normalize its rollback result to false. Preserve row errors for re-rendering. This works on **7.0 and 8.1; executed outside fixture transactions**. No schema/data conversion is required.

**Validation:** submit a first valid row with a newly introduced DOI and rich body, followed by an invalid row. Assert false/422, preserved errors, and no new Import, Note, Citation, rich text or attachment associations. Existing tests stopped at a preview assertion before their apply assertion in one failing variant; a green test suite must not substitute for this independent transaction test. Also validate a late persistence failure after a successful preview.

**Rollout/rollback:** ship this fix before new framework writers. Rollback cannot undo partially committed imports already created by an unfixed new process. If exposure occurs, audit affected batches and repair by reviewed domain-aware deletion/reimport, not by blindly replaying the CSV; imports are not idempotent.

**Code:** [Provider initializer](file:///home/user/workspace/repo/app/models/citation/provider.rb#L13-L15), config/secrets.yml, [retry declaration](file:///home/user/workspace/repo/app/jobs/citation_enrichment_job.rb#L4-L9), citation request tests.

A later focused cleanup can move the provider mapping into its own config YAML. Update tests that read/mutate `.secrets`, and refresh ownership documentation when implemented. Do not silently replace environment-backed development settings with nonexistent encrypted credentials. [7.2 Railties removals](https://github.com/rails/rails/blob/v7.2.0/railties/CHANGELOG.md).
- `wait: :exponentially_longer` is removed in **7.2**. At the **7.1 step**, rename to `:polynomially_longer`; it preserves the existing quartic delay and jitter, not exponential growth. **This symbol does not work on 7.0**; do not ship it as an unguarded preparatory change there. [7.1](https://github.com/rails/rails/blob/v7.1.0/activejob/CHANGELOG.md), [7.2](https://github.com/rails/rails/blob/v7.2.0/activejob/CHANGELOG.md) tagged changes.

### 1.8 Reminder scheduling and DST conversion

**Code:** [Note#schedule_reminder:61](file:///home/user/workspace/repo/app/models/note.rb#L56-L68), [next-day preview:44](file:///home/user/workspace/repo/app/models/note.rb#L40-L45), reminder partial/controller tests.

- Pass `Time.at(reminder_epoch)` to `set(wait_until:)`, not the integer epoch. 7.1 moves scheduling metadata to Time; 8.1 tries to serialize `.utc` and raises on Integer. **Time input works on both; executed**, retaining exact seconds and replacement job IDs. Validate imported epoch 1,793,451,617, user-entered local times, past-due delivery, replacement and deleted notes. The adapter's numeric queue score is separate from its serialized metadata. [7.1 AJ changelog](https://github.com/rails/rails/blob/v7.1.0/activejob/CHANGELOG.md), [8.1 core](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/core.rb).
- **Behavior decision, not opt-in defaults:** in Rails 8.1 `TimeWithZone#to_time` always preserves the named zone, even with old defaults. Across the November 2026 DST boundary, the app's elapsed-day preview changes from **09:00 −04:00** to **08:00 −05:00**, the same instant. For a behavior-preserving framework upgrade, explicitly construct a fixed-offset Time (`Time.at(reminder_epoch).getlocal(reminder_at.utc_offset) + 86_400`), **executed on both versions**. Alternatively, deliberately adopt the correctly localized 08:00 preview in a separate behavior change and update the documented contract and test. Do not accidentally switch from 24 elapsed hours to one calendar day. [8.1 AS changelog](https://github.com/rails/rails/blob/v8.1.0/activesupport/CHANGELOG.md), [implementation](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/time_with_zone.rb).

**Stored/scheduled work:** keep numeric reminder epochs, `reminder_job_id`, original Active Job job IDs and `reminder_sent_at`. Old scheduled jobs must remain harmless when replaced; recreating them with new IDs can invalidate this guard. Inventory schedule/retry/dead sets, not just the immediate queue, before claiming a drain.

### 1.9 Digest UTC day and BigDecimal wire format: mixed-worker blocker

**Code:** [User#request_digest](file:///home/user/workspace/repo/app/models/user.rb#L34-L56), [DigestJob](file:///home/user/workspace/repo/app/jobs/digest_job.rb), [DigestMailer](file:///home/user/workspace/repo/app/mailers/digest_mailer.rb#L6-L10), digest request tests.

**Two independent changes:**

1. Rails **7.2** serializes the named zone for TimeWithZone arguments. Previously the worker reconstructed the time in UTC. At 2026-10-05 03:30 UTC, an Eastern reader's new payload now reconstructs as October 4, 23:30. The unchanged mailer selects **October 4** although the Redis reservation is for **October 5 UTC**. This is unconditional framework behavior, not prevented by old defaults. Normalize the received time with `.utc` before computing both `@date` and `all_day`. **Works on current; executed:** final tests retain the October 5 subject/content. Test both UTC and local midnight boundaries, with included/excluded ready and draft notes on neighboring days. [7.2 AJ change](https://github.com/rails/rails/blob/v7.2.0/activejob/CHANGELOG.md), [8.1 serializer](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/serializers/time_with_zone_serializer.rb).
2. Rails **7.1** introduces BigDecimalSerializer (a gated migration there); **7.2** removes the old primitive path. New payloads reference `ActiveJob::Serializers::BigDecimalSerializer`, unknown to Rails 7.0. **Executed:** old reader rejects new original arguments with `ActiveJob::DeserializationError`; new reader accepts old JSON completion strings. Existing Active Job tests do not reproduce the production JSON conversion. [7.1](https://github.com/rails/rails/blob/v7.1.0/activejob/CHANGELOG.md), [7.2](https://github.com/rails/rails/blob/v7.2.0/activejob/CHANGELOG.md) migration notes.

**Recommendation:** while still on 7.0, serialize the completion as an explicit decimal string using `reading_completion.to_s("F")`, and make all digest consumers explicitly use UTC. DigestMailer already accepts strings through BigDecimal conversion, and on target also accepts actual BigDecimal; do not break consumption of old payloads. **Executed:** compatible full DigestJob envelopes deserialize in both directions, preserve job IDs and yield October 5 UTC plus `"0.6667"`. No custom serializer is necessary.

**Rollout:** deploy this producer/consumer bridge to every old web/worker process before new producers can enqueue. Pause digest production during the handoff if that cannot be guaranteed. Old 7.0 jobs already in Redis have plain-string completion and no named-zone metadata; new workers can read those. New unbridged BigDecimal jobs in immediate/retry/scheduled/dead storage prevent a safe rollback to 7.0; inventory and drain/process them with compatible workers rather than blindly re-enqueueing, which can duplicate email and conflict with two-day reservation keys. Preserve reservation keys/UTC date/TTL; do not clear them to make the upgrade appear healthy.

### 1.11 Resolved dependency constraint discovered in this exact target

**Code:** Gemfile/Gemfile.lock and every JSON decode path, including sessions and tags.

The requested exact **Rails 8.1.0** permits resolution to **json 3.1.0** as of this assessment. Its `ActiveSupport::JSON.decode` calls `JSON.parse(json, options)` with a second positional argument, whereas json 3.1.0 accepts options as keywords. **Executed failure:** `wrong number of arguments (given 2, expected 1)` during note persistence and session decoding, with complete stack in `target-create.log`.

**Recommendation:** constrain `json < 3` for this exact target and lock the resolution; the experiment resolves **json 2.21.2** and the error disappears. This upper bound also permits the current runtime's JSON 2.x, but the final current candidate did not add a dependency already supplied by Ruby. Do not infer that an arbitrary later Rails patch fixes this: select and assess such a target separately. Sources: [Rails 8.1.0 decoding](https://github.com/rails/rails/blob/v8.1.0/activesupport/lib/active_support/json/decoding.rb); installed JSON 3.1.0 signature and resolved lock/logs retained in evidence. Verify JSON decode/encode, sessions, tags, JSONB, and full job envelopes on the locked bundle.

## 3. Sidekiq, Redis, assets and stored-file decisions

### Sidekiq does not need to be upgraded just to resolve Rails 8.1.0

**Executed resolution:** Rails **8.1.0 + Rack 2.2.24 + rack-session 1.0.2 + rackup 1.0.1 + Puma 5.6.9 + Sidekiq 6.5.12 + Redis gem 4.8.1** resolves. Rails 8.1.0 Action Pack requires Rack ≥ 2.2.4, not Rack 3. A blanket claim that Sidekiq 6 creates a Rack dependency conflict would be false here. [Tagged gemspec](https://github.com/rails/rails/blob/v8.1.0/actionpack/actionpack.gemspec).

Rails 8.1 deprecates its built-in Sidekiq adapter and recommends Sidekiq **7.3.3+** for the gem-owned adapter; removal is planned for **8.2**, not this target. [Adapter source](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/queue_adapters/sidekiq_adapter.rb). Retaining 6.5 temporarily is a compatibility scope decision, not an assertion of long-term operational/security suitability. Real workers were not executed.

If deliberately adopting Sidekiq 7 in a separate step:

- Native `Notebook#request_export` sends `{ format: "markdown" }`; strict JSON arguments now raise. Change to `{ "format" => "markdown" }` now; this **works on 7.0/Sidekiq 6 and was executed** in final candidates. Existing fake-mode tests JSON-normalize symbols and thus hide this future rejection; enable strict arguments on 6.5 in an isolated validation run.
- `User#request_digest` uses `Sidekiq.redis { |r| r.sadd(...) }` as a boolean. Sidekiq 7 exposes redis-client connections, with integer command results: **zero is truthy in Ruby**, so duplicates may enqueue. Use an explicit added-count comparison through a tested supported Redis command API, not blanket truthiness. Preserve reservation release-on-failure and TTL. Validate two requests from the same reader/date enqueue once, and another reader/new UTC date enqueue independently. This migration was **source-assessed, not executed**.
- `Notebook#request_export` rescues `Redis::BaseError`; inspect/adapt it for redis-client errors so failed enqueue does not strand a queued Export. Test a real isolated Redis connection refusal and assert row cleanup. Verify exception classes in the selected Sidekiq version rather than assuming redis-rb errors still cover it.
- Redis server ≥ **6.2** is required by Sidekiq 7; actual deployment version is unknown.
