# Margin Notes: Rails 7.0.8.7 → 8.1.0 assessment

## Recommendation and evidence boundary

Do not deploy this as a Gemfile-only update. Upgrade through 7.1, 7.2, 8.0 and 8.1 validation checkpoints, initially retaining `config.load_defaults 7.0`. Fix removed APIs and preserve the application's explicit data and time contracts first; adopt new defaults separately.

This is a source-based assessment of the working tree and exact upstream tags, not an executed upgrade. No application boot, dependency resolution, tests, database commands, workers, or external-service experiments were run. No application files were changed. The current lockfile confirms Rails 7.0.8.7, Ruby 3.3.6, Sidekiq 6.5.12, redis 4.8.1, Rack 2.2.24, Puma 5.6.9, pg 1.6.0, Sprockets Rails 3.5.2 and Minitest 5.27.0. There is no resolved 8.1.0 bundle or test output to report. Validation below is proposed, not passed.

Ruby 3.3.6 satisfies Rails 8.1's Ruby ≥3.2 requirement. Keep Ruby unchanged for the upgrade comparison. Do not infer compatibility of the entire bundle from this fact. In particular, do not assert a mandatory Rack 3/Sidekiq major upgrade: the exact [8.1.0 Action Pack gemspec](https://github.com/rails/rails/blob/v8.1.0/actionpack/actionpack.gemspec) allows Rack ≥2.2.4, and the [built-in Sidekiq adapter](https://github.com/rails/rails/blob/v8.1.0/activejob/lib/active_job/queue_adapters/sidekiq_adapter.rb) remains present (deprecated; recommends Sidekiq ≥7.3.3). Resolve conservatively first, including a compatible rack-session version; actual resolution and worker compatibility remain unverified.

## Digest payloads: required behavior preservation and mixed-version risk

`User#request_digest` passes a reader-zone TimeWithZone and BigDecimal to `DigestJob`; `DigestMailer` uses the deserialized time's `to_date` and `all_day`, and calls `BigDecimal(params[:completion])`. The UI and reservation key promise **UTC-day** digests.

* Rails 7.0 TimeWithZone deserialization uses the job's zone (normally UTC here). Rails 8.1 includes and restores the argument's own named time zone. A 23:30 Eastern request now selects the previous local day while the Redis reservation is for the next UTC day. This is unconditional serialization behavior, not fixed by retaining old defaults.
* New Active Job BigDecimal serialization uses a named serializer; 7.0 workers do not have that built-in serializer. Old JSON-round-tripped payloads carry strings while newer payloads carry BigDecimal. The test adapter is not a substitute for this boundary.
* Preparatory change valid on 7.0: send UTC `Time` (`requested_at.utc`) and an explicit decimal string (`reading_completion.to_s("F")`). Normalize `requested_at` to UTC in the consumer too, so already-queued named-zone payloads preserve the UTC contract. Normalize completion via `.to_s` before `BigDecimal` for old/new/test-adapter values. Keep three arguments and GlobalID identity unchanged.
* Test all producer/consumer combinations (7.0→7.0, 7.0→8.1, 8.1→7.0, 8.1→8.1), **through JSON**, with distinguishable ready notes on adjacent dates at Eastern 23:30 and a nontrivial fraction such as 1/3. Assert subject date, selected notes, percent and one UTC-day reservation. Also test legacy queued payloads without `time_zone` and new payloads with it.
* Deploy the portable argument contract to every old producer first. If any new-format jobs were already emitted, stop incompatible consumers and either finish them on compatible workers or deliberately translate retained payloads; a rollback of web code alone cannot make them readable. Inventory immediate, scheduled, retry and dead sets, including framework storage jobs. Preserve job IDs (reminder suppression relies on them), retry counts and reservation keys; don't blindly flush Redis or resubmit work that can duplicate mail.

## Queue transaction semantics and optional Sidekiq upgrade

`Citation#request_enrichment` and `Note#schedule_reminder` enqueue inside row locks and rely on enqueue errors rolling back database state. Rails 8.1's actual class default for `enqueue_after_transaction_commit` is **false**; do not infer unconditional deferral from the Rails 7.2 release headline. Preserve immediate enqueue during compatibility work. If adopting deferral, Redis failure after commit no longer rolls back pending status/reminder fields: redesign that failure contract explicitly (e.g. durable dispatch/recovery), not just enable a setting. Test refusal with committed reads in a separate connection and execute a worker concurrently; fixture transactions/test adapter alone are inadequate. Intermediate 7.2 adapter/default behavior must also be inspected. The 8.1 boolean setting is not directly available as a 7.0 preparation.

A separate Sidekiq ≥7.3.3 move would remove the deprecated adapter dependency but adds its own contract changes: `Notebook#request_export` sends symbol-keyed native job options; use string keys before strict JSON enforcement (works on 7.0/current Sidekiq). `User#request_digest` assumes Redis `sadd` returns boolean and uses Redis methods through Sidekiq's connection; newer clients may return integers (0 is truthy in Ruby). Validate two identical requests and connection/error classes, and normalize against the selected client's documented API. `Notebook#request_export` rescues `Redis::BaseError`; confirm that still catches the chosen client's enqueue errors. Do not combine these changes with the Rails update without a separately resolved/tested bundle. No claim is made that unchanged Sidekiq 6 workers have been verified on 8.1.

## Rollout and rollback plan

1. **Record baseline:** exact checkout revision, lockfile, Ruby/Bundler versions, environment flags and signing-key *identity* (never secret value). Inventory persisted YAML/JSON/rich text, disk blobs, cookies/signed URLs, Redis queues/retries/schedules and digest reservations. Production deployment topology, Redis/PostgreSQL versions and actual secret source are not available from repository configuration.
2. **Prepare on 7.0:** apply only cross-compatible fixes above, especially atomic import rollback and portable digest payloads. Preserve data formats, signing keys, queue names and job classes. Observe existing scheduled/retry backlog, not just empty immediate queue.
3. **Disposable validation checkpoints:** use patched current baseline, then each minor with old defaults, then 8.1.0 with old defaults, then individual new defaults. Run `app:update` only in copies and review its diff; don't replace customized configuration wholesale. Add CSV as an explicit dependency if the isolated target bundle no longer supplies it on Ruby 3.3 (`Import` explicitly requires it). Keep existing unrelated gem pins unless resolution proves a required change.
4. **Deploy compatible consumers before producers of any new payload format**, or quiesce producers and drain/process old work on its matching runtime before switching. Verify serializers and job wrappers in both directions first. Avoid a mixed rolling deployment if those checks fail. Native exports and Active Storage purge/analyze jobs are part of the inventory, not just the three application Active Jobs.
5. **Rollback gate:** keep portable serialization and formats throughout the rollback window. Database schema changes are not required by the identified fixes; test engine migration/schema diffs before claiming none are needed. Keep old blobs and signing keys; don't regenerate local secret files if retaining development attachment signatures matters (`tmp/development_secret.txt` became `tmp/local_secret.txt`). Retain old runtime capacity to process incompatible retained work rather than deleting it. Digest delivery is not idempotent on retry; avoid duplicate replay.
6. **Defaults later:** adopt settings one at a time after behavior tests; only then raise `load_defaults`. Review 8.1 schema column reordering as dump noise, not a reason to rewrite migrations. Existing migrations remain versioned 7.0.

## Proposed validation execution and attribution

Experiments must run in a disposable copy **with isolated resources**: unique PostgreSQL database(s), including parallel test databases; dedicated Redis instance/port for Sidekiq, reservations and Cable; copy-local disk storage, cache and mail directory; local provider fake only; no production credentials or SMTP. Explicitly inspect effective database/Redis/storage settings before any boot or `db:prepare`. `REDIS_URL` alone does not isolate PostgreSQL, and a copied checkout alone does not isolate anything outside its root.

For each variant, retain: source diff, full Gemfile.lock, `ruby -v`, `bundle -v`, `bundle list`, sanitized effective settings, exact commands, stdout/stderr/exit status, Rails log and worker/provider log. Suggested layout: `variant/commands.txt`, `variant/Gemfile.lock`, `variant/config-redacted.txt`, `variant/output.log`, `variant/log/test.log`, `variant/worker.log`. There are no such executed-variant logs in this assessment.

Run `bundle check`, `bin/rails zeitwerk:check`, `bin/rails test`, target request/model files, and the additional boundary cases above. Production-like boot and asset precompile should use isolated resources and a disposable signing key; test precompiled Sprockets/importmap/Action Text upload/render flows in a real browser. `bin/rails test:system` alone is not evidence of browser coverage: repository inspection found only the generated system base, no system test cases, and it expects non-headless Chrome. Add/execute concrete workflows. Test real worker JSON transport separately from Sidekiq fake/native-job drain and Active Job's test adapter.

Remaining decisions: preserve fixed-offset reminder preview as documented or deliberately change it; preserve UTC digest day as UI promises (recommended); timing of new defaults; whether to upgrade Sidekiq separately; operational inventory and accepted rollback window. Rails 8.1.0 is the requested comparison target, not a claim that the original release is the best security patch level to deploy today.
